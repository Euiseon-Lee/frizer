# 일괄 등록 양식 및 처리 흐름 초안

갱신일: 2026-09-13. 상태: 첫 출시 정책 확정, 양식·구현 설계 중 / 구현 미착수.

정책·구현·검증의 기준 문서는 [STEP 3 보고서](STEP3_REPORT.md)다.
이 문서는 엑셀 양식과 처리 흐름을 구체화하는 보조 문서이며 별도 정책 원본으로 사용하지 않는다.
이전 초안의 수정·소비·폐기는 후속 범위로 이동했다.

## 확정 정책

- 첫 출시는 **새 MASTER와 첫 ITEM 등록 / 기존 MASTER에 새 ITEM 추가**만 지원한다.
- 기존 ITEM 수정·소비·폐기는 첫 출시에서 지원하지 않는다. 해당 작업을 지정한 행은 오류로 안내한다.
- 업로드 미리보기, 행별 검증, 전체 반영 직전 재검증, 중복 업로드 방지를 제공한다.
- 한 행이라도 오류가 있으면 전체 반영하지 않는다. 반영 중 실패해도 전체 트랜잭션을 취소한다.
- 업로드만으로 재고를 변경하지 않는다. 사용자가 미리보기를 확인한 후 반영한다.
- 이름이 같아도 MASTER를 자동 통합하지 않는다.
- 기존 음식 추가는 MASTER를 식별하고 새 ITEM을 만든다. 기존 ITEM 잔량을 증가시키지 않는다.
- 파일에서 행을 제거한 것은 삭제·소비·폐기로 해석하지 않는다.
- 실제 데이터 삭제는 웹의 명시적 오등록 정정 도구에서만 수행한다.
- 삭제 대상 ITEM·History 건수와 MASTER 전체 삭제 범위를 먼저 표시하고 재확인한다.
- ITEM과 관련 History 삭제는 하나의 트랜잭션에서 처리한다. FK RESTRICT와 명시적 삭제 순서를 사용한다.
- 분리 부모·자식 등 연결 관계의 세부 삭제 처리는 STEP 3 보고서의 설계를 따른다.

## 사용자 요구

- 초기 재고와 장본 음식을 한꺼번에 등록한다.
- 일상 소비·폐기는 모바일 웹에서 처리한다.
- 실제 구현 전 엑셀 양식을 검토한다.

## 제안 흐름

양식 준비 → 새 음식 또는 기존 음식 재고 추가 입력 → 업로드 → 행별 검증·미리보기
→ 사용자 확인 → 전체 재검증 → 한 트랜잭션으로 반영.

다음은 열 구성 예시이며 실제 양식은 미확정이다.

| 작업 | MASTER 식별값 | 음식명 | 수량 | 단위 | 용량 | 보관 위치 | 출처 | 소비기한 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 새 음식 등록 | 비움 | 두부 | 2 | 모 | 300g | 냉장실 | 장보기 | 2026-09-20 |
| 기존 음식 재고 추가 | 기존 MASTER 선택값 | 케첩 | 1 | 병 | 500g | 실온 | 장보기 | 2027-03-01 |

- MASTER 연결을 위한 식별값과 업로드 행 중복 방지 식별값은 서로 다른 용도다.
- 같은 MASTER에 여러 구매분을 추가하는 행은 정상이다. MASTER ID가 반복된다는 이유로 오류 처리하지 않는다.
- 알 수 없는 MASTER, 식별값과 음식 정보의 불일치는 확인 대상으로 처리한다.
- 신규 ITEM ID는 서버가 생성한다. 사용자가 기존 ITEM ID를 입력해 추가 구매를 처리하지 않는다.
- 날짜·냉동 정보·메모 등 선택 열과 MASTER 선택 UX는 양식 설계에서 정한다.
- 동일 파일의 여러 신규 행을 새 MASTER 하나로 연결하는 방식도 별도로 정한다. 이름만으로 묶지 않는다.

## 검증 및 식별 원칙

- 수량과 단위는 별도 입력하며 웹 등록과 동일한 검증·정규화 정책을 사용한다.
- 오류는 행 번호와 항목명으로 표시한다.
- 미리보기 이후에도 대상 MASTER의 존재·변경 여부와 제약을 재검증한다.
- 등록만 지원하더라도 중복 제출·파일 재업로드 방지와 반영 직전 검증은 필요하다.
- 같은 MASTER의 반복 사용과 같은 업로드 행의 재처리를 구분한다.
- 파일/행 식별 및 서버 요청 토큰의 구체 방식은 미확정이다.

## 후속 범위

- 현재 재고 내보내기 후 기존 ITEM 정보 수정·소비·폐기 반영.
- 이때 기존 행은 MASTER ID가 아닌 ITEM ID로 식별한다.
- 다운로드·미리보기 이후 웹에서 변경된 ITEM의 버전 충돌을 검증한다.
- 무변경 행 건너뛰기와 동일 ITEM의 중복 작업 행 처리 정책을 별도 설계한다.
- 후속 범위에서도 파일에서 사라진 행은 변경 없음이며 물리 삭제를 지원하지 않는다.

## 결정할 사항

1. 기본·선택 열, 양식 제공 방식, 한 번에 처리할 행 수.
2. 기존 MASTER 선택과 새 MASTER에 여러 행을 연결하는 방식.
3. 파일·행 식별과 중복 업로드 방지 방식, 동일 내용의 실제 재구매 구분.
4. 검증 오류 및 반영 결과 화면 구성.

오류 시 전체 미반영과 첫 출시 작업 범위는 확정 사항이며 다시 미결정 항목으로 취급하지 않는다.
다운로드·업로드 코드와 엑셀 템플릿은 아직 구현하지 않았다.
