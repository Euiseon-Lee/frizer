# 일괄 등록 양식 및 처리 흐름 초안

갱신일: 2026-09-16. 상태: 첫 출시 범위 구현, 통합 검증 완료.

정책·구현·검증의 기준 문서는 [STEP 3 보고서](STEP3_REPORT.md)다.
이 문서는 엑셀 양식과 처리 흐름을 구체화하는 보조 문서이며 별도 정책 원본으로 사용하지 않는다.
이전 초안의 수정·소비·폐기는 후속 범위로 이동했다.

## 확정 정책

- 첫 출시는 **새 MASTER와 첫 ITEM 등록 / 기존 MASTER에 새 ITEM 추가**만 지원한다.
- 기존 ITEM 수정·소비·폐기는 첫 출시에서 지원하지 않는다. 해당 작업을 지정한 행은 오류로 안내한다.
- 업로드 미리보기, 행별 검증, 전체 반영 직전 재검증, 중복 업로드 방지를 제공한다.
- 한 행이라도 오류가 있으면 전체 반영하지 않는다. 반영 중 실패해도 전체 트랜잭션을 취소한다.
- 업로드만으로 재고를 변경하지 않는다. 사용자가 미리보기를 확인한 후 반영한다.
- 이름이 같아도 MASTER를 자동 통합하지 않는다.
- 기존 음식 추가는 MASTER를 식별하고 새 ITEM을 만든다. 기존 ITEM 잔량을 증가시키지 않는다.
- 파일에서 행을 제거한 것은 삭제·소비·폐기로 해석하지 않는다.
- 실제 데이터 삭제는 웹의 명시적 오등록 정정 도구에서만 수행한다.
- 삭제 대상 ITEM·History 건수와 MASTER 전체 삭제 범위를 먼저 표시하고 재확인한다.
- ITEM과 관련 History 삭제는 하나의 트랜잭션에서 처리한다. FK RESTRICT와 명시적 삭제 순서를 사용한다.
- 분리 부모·자식 등 연결 관계의 세부 삭제 처리는 STEP 3 보고서의 설계를 따른다.

## 사용자 요구

- 초기 재고와 장본 음식을 한꺼번에 등록한다.
- 초기 데이터는 아직 정리 전이며, 사용자가 엑셀 양식에 직접 입력한다.
- 일상 소비·폐기는 모바일 웹에서 처리한다.
- 초기 양식 초안을 제공했다. 이후 사용자가 데이터 정리보다 기능 개발 완료를 우선 요청하여 다운로드·업로드 흐름까지 구현했다.

## 제안 흐름

양식 준비 → 신규 등록 또는 추가 등록 입력 → 파일 1개 업로드 → 행별 검증·미리보기
→ 하단 등록 완료 → 전체 재검증 → 한 트랜잭션으로 반영.

하단에는 목록으로·등록 완료를 항상 표시한다. 등록 완료는 유효한 미리보기 확인 후 활성화한다. 파일을 바꾸면 이전 미리보기의 등록 버튼을 비활성화하고 새 미리보기를 요구한다.

### 구현된 엑셀 양식

- 진입: 음식 등록 화면 → **일괄 등록** (`/inventory/bulk`).
- **엑셀 양식 받기**는 현재 구현과 맞는 `.xlsx` 파일을 내려받는다. 과거 `build/reports`의 검토용 초안보다 앱 양식을 우선 사용한다.
- `신규 등록`: 4행 열 이름, 5행부터 입력. 한 행마다 새 MASTER와 첫 ITEM을 만든다.
- `추가 등록`: 기존 음식명 선택 후 새 ITEM을 등록한다. 음식 번호·분류는 자동 표시한다.
- `기존 음식`: 다운로드 시점의 음식 선택 목록·번호·분류. 목록 범위는 실제 데이터가 있는 마지막 행까지다.
- `안내`: 입력과 연결 규칙. 사용하지 않는 등록 시트는 삭제하지 않고 비워둔다.
- 파일 1개, 최대 2MB. **신규 등록·추가 등록 두 시트 합계 최대 500개 항목**이다.
- 각 등록 시트에 100개 입력 행(5~104행)과 유효성 검사를 준비한다. 이후 빈 입력 행을 복사해서 사용하며, 서버는 100행 이후도 합계 제한까지 읽는다.
- 보관 위치·출처·냉동 구분은 해당 열에만 드롭다운을 제공한다. 날짜는 Excel 날짜 또는 yyyy-mm-dd 문자열을 지원한다.

| 시트 | 열 순서 |
| --- | --- |
| 신규 등록 | 음식명, 수량, 단위, 용량, 출처, 출처 메모, 보관 위치, 냉동일, 냉동 구분, 유통기한, 소비기한, 구매일, 개봉일, 메모 |
| 추가 등록 | 기존 음식명 선택, 음식 번호(자동), 분류(자동), 수량, 단위, 용량, 출처, 출처 메모, 보관 위치, 냉동일, 냉동 구분, 유통기한, 소비기한, 구매일, 개봉일, 메모 |

### 음식 연결

- 음식 묶음은 일괄 등록에서 지원하지 않는다. 신규 등록은 이름이 같아도 행마다 별도 음식을 만든다.
- 추가 등록의 A열에서 기존 음식을 선택한다. 같은 이름도 번호로 구분한다. 선택을 비운 행은 오류이며 신규 등록으로 바꾸지 않는다.
- B열 번호와 C열 분류는 기존 음식 시트를 참조한다. 서버는 지정 수식만 허용하고 수식이나 캐시를 실행·신뢰하지 않으며, A열 선택값을 현재 DB와 대조한다.
- 직접 입력된 자동 번호·분류가 대상 음식과 다르면 오류 처리한다. 다운로드 후 대상 음식이 변경되면 최신 양식을 안내한다.
- 같은 기존 음식을 여러 행에서 선택할 수 있다. 각 행은 새 ITEM을 만들고 기존 ITEM 잔량은 바꾸지 않는다.
- 이전 ‘입력’ 단일 시트 양식은 재다운로드를 안내한다. 이전 양식으로 만든 미완료 미리보기도 새 양식으로 다시 확인한다.
- 신규 등록 시트는 사용자 샘플에 맞춰 분류 입력을 제외한다. 분류가 필요하면 등록 후 웹에서 수정한다.

### 양식 수정 방법

- 다운로드 파일은 `src/main/resources/excel/frizer-bulk-template.xlsx`를 Apache POI 5.5.1로 읽어 만든다. 사용자가 제공한 파일의 열 너비·행 높이·병합·폰트·색상을 유지하며 입력 예시는 비우고 기존 음식 목록·자동 수식·드롭다운만 갱신한다. 안내 시트는 내용과 서식을 모두 원본 그대로 보존한다.
- 기본 템플릿 파일을 Excel에서 열어 너비·색상·글꼴·병합을 수정하고 저장한 후 `processResources`로 실행 리소스를 갱신하면 로컬 8080 다운로드에 반영된다. 엑셀 파일만 변경한 경우 앱 재시작은 필요하지 않으며 Java 변경은 빌드·재시작해야 한다. 열 이름·순서·시트 이름 또는 자동 수식을 바꾸려면 생성 코드와 업로드 파서를 함께 바꿔야 한다.
- 데이터 유효성 검사 범위는 복사해 확장할 수 있다. 붙여넣기로 검사를 우회하더라도 서버에서 수량·날짜·기존 음식 연결을 다시 검사한다.

## 검증 및 식별 원칙

- 수량과 단위는 별도 입력하며 웹 등록과 동일한 검증·정규화 정책을 사용한다.
- 파일 오류는 업로드 카드의 파일 선택 영역 아래에 표시하고, 행 오류는 시트 이름·행 번호·항목명으로 표시한다.
- 미리보기 이후에도 대상 MASTER의 존재·변경 여부와 제약을 재검증한다.
- 등록만 지원하더라도 중복 제출·파일 재업로드 방지와 반영 직전 검증은 필요하다.
- 같은 MASTER의 반복 사용과 같은 업로드 행의 재처리를 구분한다.
- 미리보기 UUID와 세션별 소유자 UUID를 서버에 저장한다. 같은 세션에서만 확인할 수 있으며 미완료 미리보기는 30분 후 만료된다.
- 확정 시 미리보기 행을 잠그고, 모든 기존 MASTER를 ID 순으로 잠근 뒤 미리보기 당시 버전을 검증한다. 한 대상이라도 바뀌면 재업로드를 안내한다.
- 항목·CREATE 이력·완료 결과·중복 방지 기록을 한 트랜잭션에 저장한다. 같은 요청 재제출은 기존 결과만 반환한다.
- 정규화한 행 내용·대상 MASTER 번호의 SHA-256으로 동일 내용의 업로드를 감지한다. 기존 MASTER 이름·분류와 버전은 중복 기준에서 제외한다.
- 이미 등록된 내용이면 미리보기에서 안내하고, 사용자가 실제 추가 유입임을 확인한 경우에만 새 항목을 만든다. 최초 미리보기 이후 다른 요청이 먼저 반영된 경우에는 재업로드가 필요하다.
- 행 순서를 바꾼 파일까지 같은 유입으로 판정하지 않는다. 실제 재구매 여부는 사용자가 판단한다.
- V14는 `food_bulk_preview`, `food_bulk_receipt`를 추가한다. 기존 재고·이력은 수정하지 않는다.

## 후속 범위

### 다음 작업: 검증 문구 유형 분류와 표시 기준 (미구현)

- 검증 결과를 단순 필수값 누락, 입력 형식·범위 오류, 항목 간 조건 오류, 자동 보정 안내, 사용자 확인 필요, 파일·세션 오류 등으로 분류한다. 최종 유형과 적용 범위는 후속 작업에서 확정한다.
- 단순 누락은 필드 이름만 모아 “누락된 필수 정보: …”로 표시할 수 있는지 판별한다.
- 원인·조건·수정 방법 설명이 필요한 경우는 문구 자체를 표시한다. 명칭만으로 해결 방법을 알 수 없는 오류를 누락 목록에 섞지 않는다.
- 유형별 묶음 표시 여부, 출력 순서·중복 제거, 색상, 등록 차단 여부와 추가 확인 필요 여부를 함께 정한다.
- 표시 문장의 내용으로 유형을 추측하기보다 검증 결과에 유형·필드·메시지를 명시하는 구조를 검토한다.
- 현재 구현된 누락 집계와 자동 보정 안내는 유지한다. 이번 작업에서는 후속 과제만 기록하며 전체 검증 체계의 분류·개편은 수행하지 않는다.


### 기타 후속 범위

- 현재 재고 내보내기 후 기존 ITEM 정보 수정·소비·폐기 반영.
- 이때 기존 행은 MASTER ID가 아닌 ITEM ID로 식별한다.
- 다운로드·미리보기 이후 웹에서 변경된 ITEM의 버전 충돌을 검증한다.
- 무변경 행 건너뛰기와 동일 ITEM의 중복 작업 행 처리 정책을 별도 설계한다.
- 후속 범위에서도 파일에서 사라진 행은 변경 없음이며 물리 삭제를 지원하지 않는다.

## 검증과 남은 범위

- 통합 테스트: 정상 등록, 시트 분리, 중복 이름 분리, 두 시트 합계 제한, 100행 이후 입력, 기존 음식 반복 사용, 숫자·날짜, 행 오류 전체 거부, 수식 거부, 파일 제한, 기존 음식 변경, 중간 DB 실패 전체 롤백, 동일 요청 재제출, 동시 업로드, 명시적 재등록, 세션 소유권·만료, 화면 렌더링·HTML 이스케이프.
- 입력 데이터의 의미는 추정하지 않는다. 텍스트 목록 자동 파싱과 CSV는 이번 범위에 포함하지 않는다.
- 기존 항목 수정·소비·폐기·분리 및 오등록 삭제는 일괄 등록에 포함하지 않는다.
- 앱 로그인/사용자별 재고 격리는 별도 운영 준비 작업이다. 세션별 업로드 확인은 계정 인증을 대신하지 않는다.

### 미리보기 화면 갱신

파일 1개 선택 시 자동으로 업로드·검증하며 “미리보기를 준비하고 있어.”로 안내한다. 미리보기 요청은 화면 전체를 이동하지 않고 결과·등록 영역만 갱신한다. 파일 입력을 유지하고 02 영역으로 스크롤·포커스를 이동한다. 파일 교체·선택 해제 시 기존 결과를 숨기고 등록 버튼을 비활성화하며 진행 중 요청을 취소한다. 세션 만료 시 폼 토큰을 갱신하고 파일을 다시 선택하도록 안내한다. 서버·통신 오류 후에는 입력값을 비워 같은 파일 재선택도 가능하게 한다.

### 원본 서식과 자동 보정 안내 — 2026-09-16 확정

- 안내 시트의 문장·폰트·정렬·행 높이를 코드로 덮어쓰지 않는다. 신규 등록·추가 등록의 첫 행 보조 안내도 덮어쓰지 않는다.
- 신규 등록·추가 등록의 5행 이후 기존 셀 서식을 유지한다. 값 초기화, 자동 번호·분류 수식, 드롭다운·수량 검증만 갱신하며 입력 셀 폰트 크기나 행 높이를 지정하지 않는다.
- 기존 음식 시트는 다운로드 시 DB 목록을 채운다. 원본 데이터 셀 서식을 복사하고 음식 선택 셀에 자동 줄바꿈을 적용한다. 최소 28pt 지정과 문자열 길이에 따른 행 높이 계산은 제거했다.
- 실제 Excel 날짜 셀은 표시 형식과 무관하게 날짜로 읽는다. 텍스트는 `yyyy-mm-dd`만 허용하며 `yyyy.mm.dd` 문자열은 오류다.
- 공통 입력 검증 결과는 일괄 등록 미리보기에서 확정된 말투로 변환한다. 수량 형식·범위 오류는 “수량은 0보다 큰 숫자를 소수 둘째 자리까지 입력해야해.”로 통일한다.
- 자동 보정은 오류와 구분된 안내로 표시하며, 다음 조건을 따른다.

| 냉동실이며 냉동 구분이 선택되어 있고 출처가 배달 잔반 | 직접 냉동으로 설정. “출처가 ‘배달 잔반’이면 무조건 ‘직접 냉동’으로 설정돼.” |

냉동 구분 미선택 안내와 배달 잔반 변경 안내는 동시에 출력하지 않는다. 사용자가 보관 위치를 명시한 경우 배달 잔반이라는 이유로 그 보관 위치를 덮어쓰지 않는다.

양식 다운로드와 업로드는 01 카드로 통합한다. 미리보기 버튼 없이 파일 선택 즉시 업로드·검증한다. 결과는 02 카드에 표시한다.

중복 확인 문구를 체크해야 등록 완료가 활성화된다. 서버에서도 기존의 중복 재등록 확인을 검증한다. 파일명·항목 수 요약은 미리보기 상단에서 생략하며 첨부 파일 영역에 파일명을 유지한다.

### 필수값 누락과 수량 오류 표시

- 각 행의 누락된 필수값은 “누락된 필수 정보: 음식명, 수량, 단위, 보관 위치” 형태로 마지막 한 줄에 모은다. 실제로 누락된 항목만 위 순서로 표시한다.
- 수량이 비어 있으면 누락에만 포함한다. 입력된 수량이 0 이하·소수 셋째 자리·정수 9자리 초과·숫자가 아닌 경우 수량 오류를 표시하며 수량 누락 오류를 중복 표시하지 않는다.
- 추가 등록은 음식명을 직접 입력하지 않으므로 음식명 누락을 표시하지 않는다. 기존 음식 미선택·선택 형식 오류는 “기존 음식명 선택 드롭다운에서 음식을 선택해줘.”로 안내한다.
- 보관 위치가 비어 있어도 배달 잔반 자동 설정이 적용되는 경우 누락으로 표시하지 않는다. 보관 위치를 입력했지만 목록에 없는 값이면 선택 오류만 표시한다.
- 누락 집계는 표시 방식 변경이며 양식 검증·수량 상한·자동 보정·전체 등록 차단 정책은 유지한다.
