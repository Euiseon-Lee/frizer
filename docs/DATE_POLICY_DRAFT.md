# 식품 날짜·개봉 상태 설계 초안

상태(2026-10-05 검수): 유통기한·소비기한 분리, 경고 알림 제외(V20), 개봉 상태·확인일(V21), 개봉 해당 없음(V22)은 구현·운영 적용 완료. V20~V22 운영 적용 확인일은 2026-09-30이다. 냉장 보관 시작일은 논의 중이며 아래 제안과 구현된 규칙을 구분한다.

## 현재 동작과 한계

- 소비기한은 expired_at, 유통기한은 sell_by_at으로 각각 선택 입력·저장·표시.
- 하나만 입력하거나 둘 다 입력하거나 둘 다 비울 수 있음. 서로 대체하거나 자동 환산하지 않음.
- V4는 기존 expired_at 값을 유지하며 sell_by_at은 NULL로 추가. 기존 메모의 날짜를 자동 추출하지 않음.
- 냉동 보관 시작일은 있지만 냉장 보관 시작일은 없음.
- opened_at NULL은 개봉일 미입력일 뿐이며 미개봉을 뜻하지 않음.
- 개봉 상태와 개봉 후 3개월 정리 알림을 지원한다. 날짜가 불확실하면 확인일 기준의 최소 경과 기간을 사용한다. 제품별 권장 사용 기간은 구현하지 않음.
- 앱이 날짜만으로 섭취 가능 여부를 자동 판정해서는 안 됨.

## 제안 정보 구조

| 정보 | 제안 입력 | 의미 |
| --- | --- | --- |
| 현재 위치 보관 시작일 | 날짜 / 오늘 / 모름 | 냉장·냉동 등에 넣은 날짜. 소비기한을 대신하지 않음 |
| 유통기한 (구현됨) | 선택 날짜 | 포장에 유통기한으로 적힌 날짜. 모르면 NULL |
| 소비기한 (구현됨) | 선택 날짜 | 포장에 소비기한으로 적힌 날짜. 모르면 NULL |
| 개봉 상태 (구현됨) | 해당 없음 / 미개봉 / 개봉함 / 불확실 | 개봉일과 분리, V22 포함 |
| 개봉일 | 개봉 상태일 때 선택 날짜 | 개봉했지만 날짜를 모르는 경우도 허용 |
| 개봉 후 사용 안내 | 제품 라벨의 안내 메모 | 제품에 명시된 조건 기록. 임의 기간 생성 금지 |

UI에서는 보관 시작일을 02에, 포장 기한과 개봉 상태·개봉일을 03에 배치하는 안.
V21은 기존 opened_at이 있으면 OPENED, NULL이면 UNKNOWN으로 이전한다. 기존 항목을 미개봉으로 추정하지 않는다.
기존 expired_at은 기존 입력란의 의미인 소비기한으로 유지. 과거에 유통기한을 잘못 입력한 데이터가 있다면 별도 확인 필요.

## 시나리오별 안내 제안

- 표시 기한이 남았지만 개봉 후 6개월 경과: ‘개봉 후 6개월 경과’라는 사실과 제품별 안내 확인 필요를 표시.
  모든 소스에 공통으로 적용하는 6개월 섭취/폐기 기준을 만들지 않음.
- 유통기한 경과 + 미개봉: 유통기한 경과와 미개봉을 별도로 표시. 날짜만으로 섭취 가능을 판정하거나
  소비기한으로 자동 환산하지 않음.
- 소비기한 경과 + 미개봉: 미개봉이라는 이유로 기간을 연장하지 않음. 섭취하지 않도록 안내.
- 날짜·개봉 상태 미상: 정보 미상으로 표시. 신선함 또는 미개봉으로 추정하지 않음.
- 냉장고 입고일은 재고 정리·경과 표시용. 실제 보관 온도 이력을 증명하지 않으며 안전 판정 근거로 단독 사용하지 않음.

## 근거

- [식품안전나라 소비기한 안내](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=bbs001&menu_no=3120&ntctxt_no=1093173): 유통기한과 소비기한 정의, 보관 조건 준수 및 소비기한 경과 제품 섭취 금지.
- [USDA 소스류 개봉 후 냉장 보관 안내](https://ask.fsis.usda.gov/article/How-long-can-I-keep-condiments-in-the-refrigerator): 품목별 권장 보관 기간이 다름. 국내 개별 제품에 동일 기간을 일괄 적용하기 위한 근거로 사용하지 않음.

이 문서는 제품 설계 제안이며 특정 식품의 섭취 가능 보증이나 제조사 표시를 대체하지 않음.

## 구현된 경고 제외·냉동 정책 (2026-09-30, V20)

- 개별 구매 항목의 warning_paused_until에 제외 종료일을 저장한다. 서울 날짜 기준 당일까지 제외하고 다음 날부터 재판단한다. 영구 적용은 9999-12-31, 해제는 NULL이다.
- 제외 범위는 홈 날짜 경고와 ‘확인이 필요한 음식’이다. 원래 날짜·경과 일수·상세의 냉동 안내는 유지한다. 개봉 경과 경고도 같은 설정을 따른다.
- 소비기한·냉동일·보관 위치가 변경되면 기존 제외 설정을 해제한다. 서비스와 DB 트리거 양쪽에서 적용하며, 같은 저장 요청의 제외 설정보다 해제가 우선한다. 이후 다시 설정할 수 있다.
- 수량·메모 등 다른 정보만 변경하면 설정을 유지한다. 신규·추가 등록 기본값은 알림 켜짐이다. 수량 분리로 생긴 새 항목에는 제외 설정을 자동 복사하지 않는다.
- 직접 냉동이고 소비기한 당일 또는 이전 냉동이 기록된 경우, 포장 소비기한 기준의 기한 초과·당일 경고 대신 냉동 경과 안내를 사용한다. 기한 이후 냉동·냉동일 미상·시판 냉동식품은 기존 기한 판단을 유지한다. 유통기한만으로 이 예외를 적용하지 않는다.
- 식품별 새 소비기한이나 공통 냉동 보관 만료일은 만들지 않는다. 냉동 경과 안내는 섭취 안전을 보증하지 않는다.

## 개봉 상태 확정 규칙 (V21)

- opening_status: UNOPENED(미개봉), OPENED(개봉함), UNKNOWN(개봉 여부 불확실). 신규/추가 등록 기본값은 UNOPENED.
- opened_at은 실제 개봉일이며 OPENED에서만 선택 입력한다. 날짜가 불확실하면 NULL로 저장한다.
- opening_confirmed_at은 OPENED로 처음 저장한 서울 날짜이다. 일반 수정과 알림 설정 변경에서는 유지한다. UNKNOWN/UNOPENED로 변경하면 두 날짜를 지우며 다시 OPENED로 변경할 때 새 확인일을 기록한다.
- 기존 정확한 개봉일 데이터에는 확인일을 추정해 채우지 않는다. 이후 OPENED 상태로 수정할 때 확인일을 기록한다.
- 정확한 개봉일이 있으면 해당 날짜, 없으면 확인일을 정리 알림 기준으로 사용한다. 후자는 ‘개봉 후 최소 N일 경과’로 표시하며 섭취 가능 기간을 뜻하지 않는다.
- 수량 분리 시 자식에 개봉 상태와 확인일을 복사한다. 개봉 상태/확인일 변경은 stock_revision을 갱신해 과거 수량 작업 취소 검증에도 반영한다.
- DB 제약으로 UNKNOWN/UNOPENED의 날짜 저장, 확인일과 실제 날짜가 모두 없는 OPENED를 차단한다.

## 개봉 해당 없음 (V22)

NOT_APPLICABLE(해당 없음)을 추가한다. 개봉 개념이 없는 음식에 직접 선택하며 출처에 따른 자동 지정은 하지 않는다. opened_at과 opening_confirmed_at은 NULL이고 개봉 경과 경고만 제외한다. 소비기한·냉동 판단 및 경고 제외 설정은 기존 정책을 유지한다. 기존 데이터 재분류와 조리일 추가는 하지 않는다.
