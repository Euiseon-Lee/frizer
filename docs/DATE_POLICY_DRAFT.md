# 식품 날짜·개봉 상태 설계 초안

상태: 유통기한·소비기한 분리 입력은 구현 완료. 냉장 보관 시작일과 개봉 상태 확장은 논의 중.

## 현재 동작과 한계

- 소비기한은 expired_at, 유통기한은 sell_by_at으로 각각 선택 입력·저장·표시.
- 하나만 입력하거나 둘 다 입력하거나 둘 다 비울 수 있음. 서로 대체하거나 자동 환산하지 않음.
- V4는 기존 expired_at 값을 유지하며 sell_by_at은 NULL로 추가. 기존 메모의 날짜를 자동 추출하지 않음.
- 냉동 보관 시작일은 있지만 냉장 보관 시작일은 없음.
- opened_at NULL은 개봉일 미입력일 뿐이며 미개봉을 뜻하지 않음.
- 개봉 여부, 개봉 후 권장 사용 기간, 개봉 경과 경고는 구현하지 않음.
- 앱이 날짜만으로 섭취 가능 여부를 자동 판정해서는 안 됨.

## 제안 정보 구조

| 정보 | 제안 입력 | 의미 |
| --- | --- | --- |
| 현재 위치 보관 시작일 | 날짜 / 오늘 / 모름 | 냉장·냉동 등에 넣은 날짜. 소비기한을 대신하지 않음 |
| 유통기한 (구현됨) | 선택 날짜 | 포장에 유통기한으로 적힌 날짜. 모르면 NULL |
| 소비기한 (구현됨) | 선택 날짜 | 포장에 소비기한으로 적힌 날짜. 모르면 NULL |
| 개봉 상태 | 미개봉 / 개봉 / 모름 | 개봉일과 분리 |
| 개봉일 | 개봉 상태일 때 선택 날짜 | 개봉했지만 날짜를 모르는 경우도 허용 |
| 개봉 후 사용 안내 | 제품 라벨의 안내 메모 | 제품에 명시된 조건 기록. 임의 기간 생성 금지 |

UI에서는 보관 시작일을 02에, 포장 기한과 개봉 상태·개봉일을 03에 배치하는 안.
기존 opened_at이 있으면 개봉 상태로 이전 가능하지만, NULL 데이터는 모름으로 이전해야 함.
기존 expired_at은 기존 입력란의 의미인 소비기한으로 유지. 과거에 유통기한을 잘못 입력한 데이터가 있다면 별도 확인 필요.

## 시나리오별 안내 제안

- 표시 기한이 남았지만 개봉 후 6개월 경과: ‘개봉 후 6개월 경과’라는 사실과 제품별 안내 확인 필요를 표시.
  모든 소스에 공통으로 적용하는 6개월 섭취/폐기 기준을 만들지 않음.
- 유통기한 경과 + 미개봉: 유통기한 경과와 미개봉을 별도로 표시. 날짜만으로 섭취 가능을 판정하거나
  소비기한으로 자동 환산하지 않음.
- 소비기한 경과 + 미개봉: 미개봉이라는 이유로 기간을 연장하지 않음. 섭취하지 않도록 안내.
- 날짜·개봉 상태 미상: 정보 미상으로 표시. 신선함 또는 미개봉으로 추정하지 않음.
- 냉장고 입고일은 재고 정리·경과 표시용. 실제 보관 온도 이력을 증명하지 않으며 안전 판정 근거로 단독 사용하지 않음.

## 근거

- [식품안전나라 소비기한 안내](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=bbs001&menu_no=3120&ntctxt_no=1093173): 유통기한과 소비기한 정의, 보관 조건 준수 및 소비기한 경과 제품 섭취 금지.
- [USDA 소스류 개봉 후 냉장 보관 안내](https://ask.fsis.usda.gov/article/How-long-can-I-keep-condiments-in-the-refrigerator): 품목별 권장 보관 기간이 다름. 국내 개별 제품에 동일 기간을 일괄 적용하기 위한 근거로 사용하지 않음.

이 문서는 제품 설계 제안이며 특정 식품의 섭취 가능 보증이나 제조사 표시를 대체하지 않음.
