## 확정된 정책

- 개봉 상태 순서: 해당 없음(NOT_APPLICABLE) / 미개봉(UNOPENED) / 개봉함(OPENED) / 불확실(UNKNOWN). 출처와 무관하게 직접 선택하고 신규 기본값은 미개봉이다.

음식 번호(master_id)와 구매 항목 번호(food_id)는 다르다. 예: 음식 #100의 구매 항목은 food_id 101이다. 이후 DB 작업에서 혼동하지 않는다.

## 검증 및 후속 확인

- V22 당시 전체 검증: Java 564건, JavaScript 58건, bootJar 성공(2026-09-30), GitHub CI 성공. 현재 기능의 마지막 전체 검증은 위 Java 599건·JavaScript 66건 기록을 따른다.
- 운영 테스트 계정 로그인과 등록 화면의 네 가지 개봉 상태 표시, DB V22 적용을 확인했다. 실사용 데이터의 상태/소분일 메모는 SQL 재조회로 검증했다.
- 실제 iPhone Safari의 날짜 선택·삭제·빈 값/입력 값 높이·영구 적용 전환은 별도 실기기 확인 대상이다. Chromium 검증을 Safari 완료로 간주하지 않는다.
- 엑셀 원본의 열/서식은 사용자 수정본을 보존한다. 다운로드 과정에서 선택 목록·조회 수식·일부 안내를 코드가 갱신한다. 원본 안내만 고치면 덮어써질 수 있다는 구조상 주의점은 남아 있다. 이 정리 작업을 별도 승인 없이 확대하지 않는다.
- 관리자 전체 사용자 데이터 조회는 미래 작업이며 현재는 ADMIN/USER 등급 기반과 사용자별 데이터 격리만 있다.

## 다음 세션 시작

먼저 이 문서와 OPERATIONS.md, git status를 확인한다. 이미 완료한 운영 데이터 보정을 반복하지 않는다. 새 작업 범위는 사용자에게서 받은 후 진행한다.

이번 세션 후 이어갈 순서:
1. 문서 검수는 사용자 요청으로 커밋하며 푸시는 보류한다. 다음 논의는 소비·폐기 실제 시점과 기록 시점의 분리, 구매·소비 순위, 출처·음식 종류·준비 방식 분류 등 통계 설계다. 정책 확정 전 구현·운영 데이터 변경은 진행하지 않는다.
2. 실제 모바일에서 히스토리 아코디언·음식명/기간/개수 검색·날짜 입력/삭제·상세 줄바꿈을 확인한다. 로그인 탭 복원·장시간 방치·다른 탭 로그인/로그아웃·오프라인 복귀와 기존 날짜/영구 알림 UI도 실기기 확인 대상이다.
3. 사용자가 푸시를 요청하면 기능 브랜치 푸시 → PR → 필수 test 확인 순으로 진행한다. master 병합은 운영 배포 승인 범위에서만 수행한다. 배포 후 Render Live 커밋과 실제 화면을 확인한다.
4. 새 기능은 사용자에게 범위를 받은 뒤 진행한다. 관리자 사용자별 데이터 조회·통계 대시보드는 미구현이다. 완료된 물리 삭제·운영 보정·계정 생성을 재작업하지 않는다.

로컬 실행/배포 명령은 [개발 안내](README.md), [운영 안내](OPERATIONS.md)를 따른다. Java 21과 Docker가 필요하다. 로컬 DB와 운영 Neon을 혼동하지 않는다.
