# 개별 구매 항목 이동·분리 구현

최종 갱신일: 2026-11-22.

## 전체·일부 수정과 합치기 — 현재 정책

### 수정 대상

| 구분 | 전체 수정 | 일부 수정 |
|---|---|---|
| 기본 상태 | 처음 진입할 때 선택 | 일부 수량은 빈칸 |
| 수량 의미 | 현재 구매 항목의 잔량 보정 | 원래 항목에서 분리할 수량 |
| 수량 조건 | 기존 수량·단위 검증 | 0 초과, 현재 잔량 미만, 소수 둘째 자리까지 |
| 음식명·분류 | 기존처럼 그룹의 다른 항목에도 적용 | 비활성화, 원래 그룹의 값 유지 |
| 단위 | 변경 가능 | 비활성화, 기존 단위 유지 |
| 날짜·위치·메모 등 | 현재 구매 항목에 적용 | 분리한 항목에만 적용 |
| 합치기 선택 시 | 현재 구매 항목 전체만 대상 그룹으로 이동 | 분리한 항목만 대상 그룹으로 이동 |

- 일부 수량 선택만으로 저장하거나 분리하지 않는다. 항목 정보 변경 또는 유효한 합칠 대상이 필요하다. 일부 수정에서 전량을 입력하면 저장 버튼을 비활성화하고 범위 안내를 표시한다.
- 전체/일부 탭을 바꾸면 모든 입력·검색·합치기 선택을 저장된 원본 기준으로 초기화한다. 전체 수량은 원래 잔량, 일부 수량은 빈칸이다.
- 전체 수정은 기존 직접 저장 흐름을 유지한다. 별도의 ‘어느 만큼 수정할까’, ‘음식 변경’, ‘옮기자’ 화면을 추가하지 않는다.

화면 배치·문구·입력 상태는 [UI 규격](UI_DESIGN.md)의 전체·일부 수정 절을 따른다.

### 저장 및 데이터 보존

- POST `/inventory/{id}/edit`에서 전체/일부 여부, 합치기 대상·버전, 항목 수정 시각을 확인한다. 사용자 소유권과 항목 상태를 검증한다.
- `ItemEditService`는 그룹 ID 순서대로 잠근 뒤 필요 시 분리 → 항목 수정 → 대상 그룹 이동을 한 트랜잭션으로 처리한다. 어느 단계에서 실패해도 분리·차감·이력을 함께 원복한다.
- 일부 수정은 원본의 선택 수량만 차감하고 새 구매 항목을 만든다. 원본의 나머지 정보와 다른 구매 항목은 유지한다. 개봉일·확인일·조리일 등은 계승하며, 변경하지 않은 경고 일시중지 설정도 보존한다. 위치·소비기한·냉동일 변경 시 알림을 다시 켜는 기존 수정 정책은 유지한다.
- 합치기는 그룹 소속 변경이다. 기존 대상 구매 항목과 하나로 합산하지 않고 항목별 단위·날짜·메모를 보존한다. 예를 들어 3개와 2팩은 별도 항목으로 남는다.
- 분리 이력은 원본 `SPLIT_OUT`, 새 항목 `SPLIT_IN`으로 남고, 실제 변경은 `UPDATE`, 합치기는 항목별 이동 영수증으로 기록해 히스토리에 병합으로 표시한다.
- 오래된 항목/대상 버전과 중복 제출을 거절한다. 숨겨진 분류 갱신 버튼의 명령값은 저장 요청에 포함하지 않는다. 성공하면 실제 수정된 항목 상세로 이동한다.
- 예: A의 20개 중 3개를 B로 합치면 A는 17개, B는 기존 수량에 3개 항목이 추가된다. 소비가 아니므로 전체 재고량은 줄지 않는다.

### 기존 목록·상세와의 구분

- 목록의 다건 합치기는 유지한다. 기존 목록에서 보관 중 항목 전체를 선택하면 종료 항목까지 이동하는 정책도 유지한다. **수정 화면의 ‘전체’는 현재 구매 항목 전체를 뜻하며 이 목록 정책을 적용하지 않는다.**
- 개별 구매 상세의 `나누자` 링크는 제거하고 `수정하자`를 `추가 등록할래?`처럼 전체 너비로 표시한다. 기존 분리 서비스·라우트는 호환 및 내부 재사용을 위해 유지한다.
- 단독 상세의 `다른 음식하고 합치자 / 잘못 등록했어`는 현재 보관 중/종료 뷰에서 같은 그룹 항목이 1개인 경우에 표시한다. 여러 개이면 개별 목록에서 처리하는 기존 조건을 유지한다.
- 새 DB 마이그레이션은 없다. 최종 검증 범위와 재현 방법은 [테스트 기록](TEST_MATRIX.md)을 따른다.

## 목록 합치기와 저장 계약

- 목록에서는 선택한 구매 항목을 기존 음식 또는 새로운 음식 그룹으로 옮긴다. 보관 중·종료 항목 모두 지원한다. 기존 그룹은 대상 이름·분류를 계승하며 새 그룹은 이름·필수 분류를 입력한다.
- 보관 중 전체 선택 여부는 미리보기에서 확정하고 원본 그룹 버전으로 검증한다. 전체 선택이면 종료 항목도 함께 이동하며, 일부 선택이면 선택하지 않은 항목과 종료 항목은 원래 그룹에 남는다.
- GET/POST `/foods/{id}/move`와 `/choices`, `/preview`를 사용한다. 제거된 `/inventory/{id}/move`, `/foods/{id}/merge`는 현재 진입 경로가 아니다.
- 소유권·그룹 버전·선택 항목을 다시 확인하고 그룹 잠금 순서를 유지한다. 요청 영수증과 입력 지문으로 재전송을 처리하며 같은 토큰의 다른 입력은 거절한다.
- 이력은 항목별 `food_item_move_receipt`를 기반으로 병합(MERGE) 행을 표시한다. 과거 그룹 병합 영수증은 조회를 유지하되 새 쓰기 경로로 사용하지 않는다. 이동 전후 그룹 ID·당시 이름과 개별 이력을 보존한다.
- 이동 후 원본에 남은 항목이 없을 때만 빈 원본 그룹을 정리한다. 이동으로 stock_revision이 바뀌면 이전 소비·폐기 취소는 거절한다. 합치기 자체의 취소는 제공하지 않는다.

## 공통 분리 계약

- 구조화 수량의 보관 중 항목에서 `0 < 분리량 < 현재 잔량`이며 소수 둘째 자리까지 허용한다. 0.5개 중 0.25개도 분리할 수 있다. 단위를 환산하지 않는다.
- 같은 그룹 아래 새 항목을 만들고 원본을 차감한다. 원본 `SPLIT_OUT`, 자식 `SPLIT_IN`을 같은 트랜잭션에 기록하며 CREATE나 소비로 세지 않는다. 전체 히스토리는 SPLIT_OUT 한 건을 표시하고 각 항목 상세는 각자의 이력을 표시한다.
- 자식 최초 수량은 SPLIT_IN으로 보존한다. `food_split_receipt`의 사용자별 요청 ID와 원본·자식 ID로 재전송과 연결 관계를 관리한다. 별도 parent_item_id나 stock_batch_id는 도입하지 않는다.
- 날짜·출처·용량·메모·개봉 상태·확인일·조리일·경고 알림 제외 설정을 복사한 뒤 해당 작업에서 지정한 변경만 적용한다. 일부 수정의 위치·소비기한·냉동일 변경에 따른 알림 해제는 [날짜 정책](DATE_POLICY_DRAFT.md)을 따른다.
- 일반 분리는 별도 취소를 제공하지 않으며 원본의 stock_revision을 올린다. 소비에 포함된 자동 분리는 소비 취소와 함께 복원하는 별도 계약이며 [수량 정책](ITEM_QUANTITY_DESIGN.md)을 따른다.
- `/inventory/{id}/split`과 기존 분리 서비스는 유지하지만 상세에 별도 ‘나누자’ 진입을 노출하지 않는다. 일부 수정과 소비 자동 분리가 이 저장 기능을 재사용한다.
