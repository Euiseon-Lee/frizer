# 작업 정리 및 다음 논의

기준: 2026-09-14. 반복 수정한 UI는 이 문서의 최종 상태를 따른다.

## 구현 결과

- 신규 등록의 중복 제출 방지, 오류 입력 처리, 선택 대상 변경 시 취소 링크 갱신, 이동 요청 ID 경합 처리 보완.
- 화면 수량·단위는 공백 없이 표시하고 요청 안내의 ‘해줘’ 표현 통일.
- 홈 WARNING: 흰 배경, #FF4040 테두리, #FFF5F5 태그 배경, #D93636 경고 글자. 개봉 경과·당일·구분자는 #696B7A. 기존 아이콘 #FF6B6B. 경고 판정과 날짜 계산은 유지.
- 홈 WARNING 목록은 한 줄·최대 3개, 제목은 전체 대상 건수. 긴 이름·사유는 말줄임하며 전체 접근성 이름을 유지한다. WARNING 전체 목록 연결은 미구현.
- 홈 보관 위치 ‘전체’ 카드의 하트는 같은 크기의 강아지 얼굴 SVG로 변경.
- 개별 구매 목록: 날짜 2열, 유통기한/구매일 왼쪽 정렬, 소비기한/개봉일 오른쪽 정렬. 네 날짜 영역만 1pt 축소. 보관 위치·수량·단위·등록/수정 시각은 원래 크기 유지. 작은 화면은 열 안에서 필요한 줄바꿈을 허용한다.
- 구매 목록의 경고 아이콘은 제거하고 날짜 옆에 ` (+N일)` 표시. 구매 항목은 기존 경고 안내·아이콘을 유지하며 경과 일수 추가. 오늘 +0일, 미래·미입력 날짜에는 경과 표기 없음. 경고 라벨과 값은 #D93636.
- 구매 목록 하단은 ‘다른 음식으로 이동 / 구매 항목 추가’를 5:5 한 행에 배치. ‘전체 목록으로’는 다음 행 전체 너비·가운데 정렬. 두 구매 화면의 목록 이동 링크는 테두리 없이 취소와 같은 hover/focus 효과.
- 음식 이동 화면 문구 정리, 선택 목록 너비 제한·두 줄 말줄임·키보드 조작 지원. 최종 음식명은 오른쪽 정렬·왼쪽→오른쪽 읽기 방향. 되돌릴 수 없다는 안내는 별도 줄.
- 히스토리에 음식 이동 영수증을 포함하고 현재 연결 대상 안내. 태그 ‘이동’, 요약 ‘개별 구매 N건을 이동했어’. 전후 화살표 강조. ‘기존 입력’ 및 이전 등록 안내 문구 제거.
- 값이 같은 수량은 변경 이력에 포함하지 않는다. 과거 데이터 전용 렌더링 보정 로직은 추가하지 않았고, 확인된 개발 기록 한 건만 일회성 정리했다.

## 검증 및 저장 상태

- 마감 시 최종 날짜 2열·폰트·공백·아이콘 변경을 포함하여 전체 Java 테스트 389개를 다시 실행했다. 실패·오류·건너뜀 0, test bootJar 성공.
- 마감 시 JavaScript 4종(등록 UI 25개, 이동 미리보기, 새 대상 선택 목록, 쪼코 이미지 선택기)을 다시 실행하여 모두 통과했다.
- 주요 화면 320/390/448px 확인. 실제 모바일 기기 검증은 별도 필요.
- 사용자가 2026-09-14 커밋 메시지와 오늘 변경 사항의 커밋을 승인했다. 커밋 제목은 `feat: 등록 중복 방지와 음식 이동 이력 및 구매 화면 개선`이다. 푸시는 요청 범위가 아니다. 실제 저장 상태는 git status/log로 확인한다.
- Java 변경은 실행 앱을 재시작해야 반영된다. 현재 실행 앱에 모든 Java 변경이 적용되었는지는 별도 확인이 필요하다.

## 다음 논의

1. **긴 음식명 헤더**: 공통 높이 고정, 최대 3줄, 1px씩 축소·최소 16px, 초과 시 말줄임 및 전체 이름 열기 방안은 논의만 했고 미구현. 2026-09-14 사용자 결정으로 오늘 구현하지 않고 추후 작업으로 보류한다. 최소 12px 축소는 채택하지 않았으며 기존 최소 16px 안과 잘린 제목을 눌러 전체 이름을 보여주는 방식을 다음 작업 전에 다시 논의한다.
2. **WARNING 전체 보기와 필터**: 현재 보관 위치 필터만 구현. 상태 필터를 어디에 표시하고, 전체 음식에서 구매 목록으로 진입할 때 유지할지 시안으로 확인해야 한다. 홈 3개 초과 대상에 대한 전체 보기 연결도 여기에 포함된다.
3. **음식 이동의 범위**: 현재 기능은 원래 음식의 구매 항목 전체를 다른 음식으로 옮기는 기능이다. 개별 구매 항목 선택 이동·새 음식으로 분리와 마지막 항목 이동 후 빈 음식 처리 정책은 별도 미구현 범위다. ‘이동’ 명칭 변경으로 이 기능들이 구현된 것은 아니다.
4. **후속 STEP 3 우선순위**: 잔량·부분 소비/폐기·분리·처리 취소·오등록 삭제·엑셀 일괄 등록. 기존 설계 문서의 확정 정책을 우선 따르고, 미정 UI와 예외만 보완한다.

후속 논의 제안(즉시 착수 확정 아님): 긴 이름 헤더 방식 재논의 → 필터 화면 시안 논의 → WARNING 전체 보기 연결 → 다음 STEP 3 기능 선택.
