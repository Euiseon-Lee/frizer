## 원칙

- 각 항목은 착수 시 해당 기준 문서([수량 설계](ITEM_QUANTITY_DESIGN.md)·[이동 설계](ITEM_MOVE_DESIGN.md)·[UI 규격](UI_DESIGN.md) 등)를 갱신하는 방식으로 설계를 확정한다. 항목별 새 문서를 만들지 않는다.
- 운영 데이터가 쌓인 뒤의 DB 변경에는 백업·복구 검증을 선행한다.
- 원래는 STEP 4 완료 후 착수하는 계획이었으나, 실사용 요청으로 일부 항목을 앞당겨 반영했다. 남은 후보는 사용자와 범위를 정한 후 진행한다.

상태: 현재 코드의 영향 범위를 조사한 작업 목록이다. UI 방식은 확정했으며 세부 저장·전환 계약과 구현은 미완료다. 분류 이름·포함 예시·큰 틀은 [앱 개념 문서](APP_CONCEPTS.md)의 「분류 체계와 재고 통계 방향」을 기준으로 한다. UI 세부 기준은 [UI 규격](UI_DESIGN.md)에서 관리하며, 엑셀 계약 확정 후 [일괄 등록 규격](BULK_REGISTRATION.md), 실제 검증 후 [테스트 범위](TEST_MATRIX.md)를 갱신한다.

### 현재 저장 단위와 공통 원칙

- 현재 분류는 `food_master.category`의 선택 입력 자유 텍스트다. 개별 구매분이 아니라 음식 그룹의 공통 정보다. 수정 시 같은 그룹의 다른 항목에도 반영된다.
- 새로운 기준은 사전 제공 대분류·중분류와 기존 자유 입력 음식명이다. 중분류 없는 대분류도 허용한다. 새 표준 품목 단계는 만들지 않는다.
- 기존 자유 입력값, 미분류, 중분류 없는 대분류, 대분류·중분류가 모두 있는 상태를 구분해서 설계한다. 기존 값의 자동 분류·덮어쓰기는 하지 않는다.
- 2026-10-08 분류 필수 입력과 「접어서 선택」 UI를 확정했다. 선택 해제는 제공하지 않는다. 중분류가 있는 대분류는 중분류까지 선택하는 UI 기준으로 설계한다. 기존 미분류·자유 입력값의 전환, 추가 등록 시 보완 절차, 분류 변경의 과거 통계 반영 방식은 저장 계약에서 확정한다.

### C. 엑셀 전체 경로

웹 선택창만 변경하고 엑셀을 그대로 두면 등록 경로별 데이터 계약이 달라지므로 함께 설계한다.

- 신규 등록 양식의 기존 분류 열: 대분류·중분류 열 구성, 목록 선택 및 잘못된 조합 안내 방식 결정.
- 추가 등록 양식: 기존 음식 선택 시 분류 자동 표시, 음식명·분류·번호로 구성한 선택 라벨 갱신.
- 숨은 조회 데이터·자동 조회 수식·선택 목록: 분류 구조 변경과 열 위치의 일관성 유지.
- 업로드 파싱·검증: 필드 연결, 기존 음식 분류 일치 검사, 자동 수식 변조 검사, 행별 오류 안내 갱신.
- 이전 양식 호환: 어떤 버전을 계속 읽을지와 재다운로드 안내 조건을 확정. 과거 양식의 자유 입력 분류를 임의 해석하지 않음.
- 저장된 미완료 미리보기: 배포 전후 구조 변경 시 재업로드·재검증 정책 결정. 이미 완료된 요청의 재시도 계약 유지.
- 중복 등록 fingerprint: 신규 등록의 분류가 정규화 입력 내용에 포함된다. 새 구조가 중복 판단을 어떻게 바꾸는지 검증. 기존 receipt 삭제로 우회하지 않음.
- 원본 XLSX와 다운로드 시 코드가 갱신하는 안내·수식·검증 목록을 함께 확인. 사용자 수정 서식 보존.
- 관련 코드: `BulkWorkbook`의 headers/FIELDS/choiceLabel/양식 생성·읽기, `BulkRegistrationService`의 분류 일치·미리보기·중복 판정, `BulkValidation`, `fragments/bulk-registration.html`.

- 중분류가 없는 대분류와, 중분류가 있는 대분류의 미완료 선택을 구분하는 저장 계약 설계.
- 음식 그룹과 기준 데이터의 연결 및 부모·자식 조합 무결성 검증.

- 기준 분류 이름 변경·비활성화가 기존 음식 선택·엑셀·이력·통계에 미치는 영향 결정.
- 버전 전환 중 기존 폼·엑셀·저장된 미리보기·과거 스냅샷의 호환 정책 결정.

### E. 이번 교체에 자동 포함하지 않는 신규 기능

현재 재고 목록의 분류 필터, 히스토리 분류 검색, 추가 등록·병합의 분류 검색, 분류별 통계 화면은 없다. 기존 음식 검색은 음식명 검색이다. 분류 표시가 있다는 이유로 분류 검색도 있다고 가정하지 않는다.

- 위 필터·검색·통계 화면 추가는 별도 설계 범위로 다룬다.
- 소비·폐기·삭제에 새 분류 선택 UI를 추가하지 않는다.
- 밀키트·간편식·출처 개편, 실제 소비 날짜, 재료→완성 음식 연결은 별도 미확정 사항이다.
- 소비 텀 집계는 분류 전환과 별도 계약이 필요하다. 구매/보관 시작일·소비 기록일·실제 소비일을 구분하고, 분리·병합·취소·부분 폐기·단위 차이를 다뤄야 한다.

### F. UI 검토 순서와 필수 상태

2026-10-08 「접어서 선택」을 확정했다. 이후 진행은 기존 UI 규격에 맞춘 세부 확인 → 상세·목록 표시 확정 → 수정·추가 등록·병합과 저장 계약 → 엑셀·과거 기록 계약 → 구현·회귀 검증이다. 전체 기능 완료 전까지 기능 브랜치에서 단계별 커밋하며 master 반영·운영 배포하지 않는다.

선택칸 상시 표시안은 채택하지 않는다. UI_DESIGN.md의 분류 선택 세부 기준과 다음 상태를 실제 등록 화면에서 검증한다.

- [ ] 미선택 필수 오류, 선택 완료, 변경, 취소 시 기존 선택 복원. 선택 해제 없음.
- [ ] 중분류가 있는 대분류 선택 후 중분류 선택.
- [ ] 음료 등 중분류 없는 대분류는 중분류 입력 없이 선택 완료 가능.
- [ ] 대분류 변경으로 기존 중분류가 무효가 되는 경우.
- [ ] 임시 선택 상태에서 Enter/등록/수정/병합 미리보기 제출, 신규·추가·일괄 모드 전환 후 상태 복원.
- [ ] 접힌 필수 필드의 오류 포커스, 숨긴 중분류 required·disabled·제출값, 긴 네이티브 select 선택값.
- [ ] 기존 자유 입력 분류가 남아 있는 음식의 수정·조회.
- [ ] 추가 등록의 읽기 전용·미분류·음식 재선택·신규 모드 복귀.
- [ ] 그룹 공통 분류 수정과 병합 대상 분류 적용의 영향 안내.
- [ ] 긴 이름·예시 문구, 오류 안내, 작은 화면에서 줄바꿈과 입력 높이.
- [ ] 키보드·스크린리더 포커스, 취소 후 복귀, 뒤로 가기·탭 복원.

- **구현 전 정책 결정 필요 — 기존 음식의 필수 전환:** 현재 추가 등록은 기존 분류를 서버에서 계승하고 입력 UI를 비활성화한다. 필수 제약만 추가하면 미분류 기존 음식은 사용자가 고칠 수 없는 추가 등록 오류가 된다. 기존 음식 수정에서 분류를 먼저 보완할지, 별도 전환 흐름을 둘지 정해야 한다. 일반 수정·추가 등록·기존 음식 병합·엑셀에 같은 정책을 적용하고 입력 중인 수량·날짜를 잃지 않는 복귀 경로를 설계한다. 과거 분류 보존은 읽기 보존을 뜻하며 새 저장의 필수 조건을 통과한다는 뜻은 아니다.
