**최종 결과: 26개 통과, 실패 0, 오류 0, 건너뜀 0.** 날짜 오류 후 분류 재저장 수정까지 포함한 코드에서 26개를 모두 재실행했다. 저장 버튼 활성화 검사만으로 통과 처리하지 않았다.

### 저장 결과 확인

- 일부 3개 합치기: 원본 20→17, 대상 그룹 20→23, 전체 합계 40 유지. 분리 이력과 병합 영수증·히스토리 표시를 확인한다.
- 일반 일부 수정: 새 항목 3개에만 변경을 적용하고 나머지 17개의 메모·보관 정보는 유지한다. 전체 수량 보정은 입력값으로 바뀐다.
- 전체 합치기: 선택한 구매 항목만 옮기며 다른 구매 및 종료 항목을 함께 옮기지 않는 것은 기본 서비스 회귀에서도 확인했다.
- 잘못된 날짜를 수정한 경우: 변경한 대분류/중분류 코드와 UPDATE 이력이 저장된다. 날짜와 분류를 모두 원복하면 저장 버튼이 비활성화된다.
- 충돌·재전송: 실패 시 분리 영수증이 생성되지 않거나 추가 분리가 발생하지 않는지 확인한다.

### 재현 방법

Java 21, Docker, Node.js와 Playwright/Edge가 필요하다. `PLAYWRIGHT_MODULE`에는 설치된 Playwright 모듈의 절대 경로를 설정한다. 이 변수가 없으면 브라우저 결합 테스트는 건너뛰므로 Java 기본 테스트 통과만으로 26개를 검증했다고 표현하면 안 된다.

```powershell
$env:JAVA_HOME = 'C:/dev/frizer/.gradle/jdks/jdk21.0.12_9'
$env:PLAYWRIGHT_MODULE = '<설치된 playwright 모듈의 절대 경로>'
./gradlew.bat test --tests '*ItemEditIntegrationTest.browserSubmissionPersistsQuantityAndHistory' --tests '*ItemEditIntegrationTest.browserValidationRetryKeepsCategoryChangeSaveable' --tests '*ItemEditIntegrationTest.browserCategoryEdgeCases' --offline --no-daemon --console=plain
```

- `ItemEditIntegrationTest`: 기본 제출 분기 22개 + 날짜 오류 재저장 1개 + 분류 예외 3개.
- `src/test/browser/item-edit-submit.cjs`: 브라우저 조작·전체 FormData 캡처. 테스트 DB의 화면만 사용한다.
- `src/test/browser/item-edit-review.cjs`: 음식명 초안, 영구/날짜 알림의 변경 감지, 검색 결과 안내 회귀. 렌더링 fixture 생성 후 `node src/test/browser/item-edit-review.cjs`로 실행한다.
- 결과: `build/test-results/test/TEST-com.euiseon.friger.inventory.ItemEditIntegrationTest.xml`. 브라우저 fixture·캡처 요청·로그는 `build/reports/item-edit/browser-submit/`에 생성된다. 모두 커밋 제외 산출물이다.
