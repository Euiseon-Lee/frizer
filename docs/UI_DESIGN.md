- FoodActionType.label()을 공통 명칭으로 사용한다. 수량 이력의 ‘정정’은 ‘수정’, 히스토리 태그의 ‘처리 취소’는 ‘취소’로 통일한다. ‘처리 취소’ 버튼 문구와 동작은 유지한다.
- 히스토리의 병합 행은 표시 이벤트를 MERGE 하나로 통일한다(2026-09-17 사용자 확정): 신형(항목별 이동 영수증)과 구형(과거 통합 영수증) 모두 ‘병합’ 태그(기존 이동 색상)·data-event MERGE이며, 내용은 신형 양식 ‘음식명: A (#원본ID) → B (#대상ID)’ 한 줄로 표기한다. 제목은 당시 음식명이다. 저장 데이터(영수증·이력)는 변경하지 않는다.
- 히스토리 필드 값의 → 화살표 강조(굵은 잉크색)는 수정뿐 아니라 모든 태그의 값에 공통 적용한다(2026-09-17).
- 병합된 항목의 과거 기록 안내 문구는 “병합 처리가 완료돼서 이제는 ‘X’로 이동할 거야.”, 이름만 바뀐 경우는 “이름이 바뀌어서 이제는 ‘X’로 이동할 거야.”다(항목의 이동 영수증 유무로 구분, 2026-09-17).
- 수량 분리(SPLIT_OUT/SPLIT_IN)는 정식 명칭 ‘분리’ 태그 하나를 공유하며 전용 라벤더 색상을 사용한다. 진입·제출 버튼(‘나누자’/‘응, 나누자’)도 분리 태그 색상을 공유한다.
- 모든 화면에서 action-badge history-badge와 data-event를 사용한다. 별도 수량 이력 색상 및 화면별 크기 덮어쓰기를 제거한다.
- 글자 12px, 굵기 400, 행간 1.4, 둥근 모서리 6px. 등록부터 이동까지 모든 액션 태그에 글자색 1px 테두리와 세로 3px/가로 5px 여백을 적용한다.
- border-box로 전체 너비/높이를 명시한다. 기본 글자 크기에서 전체 36×24.8px이며, 테두리 있는 태그의 안쪽 공간만 가로/세로 2px 줄어든다.
- 위치 태그, 보관 위치 카드, WARNING!, primary 색상은 변경하지 않는다. 액션 색상은 독립된 history 토큰으로 관리한다.
- 모든 액션·위치 태그는 소속 행에서 세로 중앙 정렬한다. 히스토리 탭의 별도 여백 및 크기 설정을 제거했다.
- 먹었어/버렸어 버튼은 소비/폐기 태그의 배경·글자색을 공유한다. 다른 음식으로 병합/수정 버튼도 해당 태그 색상을 공유한다. 모든 액션 버튼 테두리는 각 태그 글자색의 1px로 통일한다.
- 오등록 삭제(2026-09-17 사용자 확정): 진입 버튼 ‘잘못 등록했어’와 제출 버튼 ‘확인했어, 지울게’는 폐기 태그 색상을 공유한다(action-delete). 삭제는 이력을 남기지 않아 전용 히스토리 태그가 없으므로 전용 색상도 배정하지 않는다. 확인 화면 제목은 ‘오등록한 항목 지우기’, 삭제 요약 라벨은 병합 미리보기와 같은 ‘개별 구매 총 건수/음식 이력 총 건수’와 ‘N건’ 표기를 쓰고, 레이아웃은 병합 확인 화면 규격을 따른다.
- 수량 변경 이력과 완료 알림의 처리 취소 버튼은 안쪽 여백을 위아래 4px/좌우 8px로 통일한다. 알림 문구와 버튼 사이의 8px gap은 별도의 바깥 간격이다. 수량 이력의 취소 열은 최소 68px를 확보한다.
- 수량 이력의 작은 처리 취소 버튼은 예외적으로 기존 스타일을 유지한다. 테두리 없음/흰색 배경/회색 글자이며 호버 시 공통 밝기 96%를 사용한다. 취소 태그 색상과 연결하지 않는다.
- 이동/수정/먹었어/버렸어 버튼은 호버와 눌림에서 현재 색상에 brightness(.96)를 적용한다. 이동 버튼의 기존 보라색 호버보다 높은 우선순위로 새 배경·글자·테두리 색상을 유지한다.
- 홈 ‘음식 등록하러 가자!’와 개별 구매 목록 ‘추가 등록’는 등록 색상과 글자색 테두리를 사용한다. 홈 버튼 오른쪽 여백은 8px이다.
- 이건 뭐야 탭의 등록/추가 등록 제출 버튼은 등록 색상, 수정 제출 버튼은 수정 색상을 사용한다. 수정 제출 문구는 ‘수정하자!’다.
- 신규 등록·추가 등록 두 탭의 제출 문구는 모두 ‘등록하자!’로 통일한다. 탭 전환 시 JavaScript도 같은 문구를 유지한다. 일괄 등록 패널의 제출은 ‘등록 완료’를 유지한다. 개별 구매 목록의 진입 버튼 ‘추가 등록’는 유지한다.

- 비활성화 버튼은 hover/active 색상과 밝기 효과를 적용하지 않는다. 해당 선택자를 :not(:disabled)로 제한하고 disabled의 filter/transition을 제거한다.
- 등록/수정 화면의 01·02·03 단계 번호 배경은 --subtle-hover-bg (#F7F7FB)를 사용한다. 글자색·여백은 유지한다.
- 실온/냉장실/냉동실 및 WARNING! 태그에는 테두리를 추가하지 않는다. 비교표의 공통 테두리 규칙이 위치·경고 색상 견본에도 적용된 오류만 수정했다. 실제 앱의 해당 태그는 원래부터 테두리가 없었다. WARNING 카드 외곽 테두리는 유지한다.
- 2026-09-16 후속 파스텔 조합을 적용했다. 7개 액션의 글자 대비는 약 5.00~6.19:1이다. 기존 테두리 유무·크기·호버 효과는 유지하며 연결된 버튼도 공통 토큰을 통해 함께 변경된다.

## 검증

- 공개 배포는 `/login`의 개인 로그인 화면으로 진입한다. 기존 입력·버튼 CSS를 재사용한다. 로그인 활성 환경에서 상단 쪼코 링크는 `/account`로 이동하며 POST 로그아웃을 제공한다. 로컬 프로필에서도 로그인 화면을 확인한다. 로그인·계정·접근 오류 화면은 공통 헤더와 page → tab-heading/tab-sheet 구조를 사용한다. 로그인 본문에는 별도 카드와 제목 없이 아이디·비밀번호·버튼을 둔다. 로그인 버튼은 공통 button의 크기·모서리·글자 규격을 유지하고, 선택된 홈 메뉴 글자 색(#7057C8)을 배경과 테두리에 적용하고 버튼 글자는 흰색으로 표시한다.

- 검색 버튼(추가 등록/음식 이동)은 공통 search-button으로 통일한다. 기본 배경 #FFFFFF, 글자 및 1px 테두리 #696B7A, 호버 밝기 96%. 기본 보라색 버튼 규칙에서 분리했다. 이전 보라색 호버 조사 결과 중 검색 버튼은 해소됐다.
- 기존 음식 선택 후 요약 영역과 긴 음식명 펼침 영역은 #F7F7FB 공통 토큰을 사용한다. 변경 버튼은 연회색 배경/회색 글자와 테두리, 밝기 96% 호버로 바꾸며 기존 크기·모서리·여백을 유지한다.

- 필수 표기는 WARNING 글자색 #D93636을 사용한다.
- 등록 방식 선택은 미선택 흰색/회색 테두리, 선택 배경 #42649A/글자 #EDF3FF/테두리 #42649A다.
- 음식 병합하기의 기존 음식으로 병합/새로운 음식으로 변경 선택은 미선택 흰색/회색 테두리, 선택 배경 #596344/글자 #FFF6D8/테두리 #596344다.
- 전체 선택 안내는 2줄·2색 구조다(2026-09-18): 첫 줄(사실 설명)은 회색 — 병합 3변형 ‘전체 항목을 선택했고, 종료된 기록이 없어./종료된 기록 N건도 함께 병합돼./모든 기록이 함께 병합돼.’, 삭제는 ‘모든 항목을 지우는 거라서 음식까지 전부 삭제할 수 있어.’ — 둘째 줄(‘이 경우 병합 시 기존 음식은 사라져.’, 병합 전용)만 경고색이다. 일부 선택 안내는 ‘항목 중 일부만 선택했기 때문에’ 같은 앞머리 없이 결과만 말한다. 연속 문구 4px는 전역 일반 규칙을 따른다(회색 블록 첫 문구 앞은 20px). 삭제의 ‘빈 음식 그룹은 남겨둘게’ 문구는 제거했고, 항목 목록에는 등록 일시를 표시하지 않는다(병합과 통일). 회색 블록 상단 라벨은 선택 범위와 무관하게 ‘병합 대상’/‘삭제 대상 항목’이다.
- 삭제 미리보기의 문구는 회색 ‘삭제한 항목은 기록 및 통계에서 사라져.’ 다음 경고색 ‘이 작업은 취소할 수 없어.’ 순서다(2026-09-18, 카드 아래 배치). 그룹 동반 삭제 체크박스는 왼쪽 12px에서 시작한다.
- 기존 음식으로 병합의 대상 선택(2026-09-18 사용자 확정): 검색 버튼·드롭다운 대신 페이지 로드 시 전체 음식 목록을 리스트 카드(merge-target-list, 내부 스크롤 최대 264px)로 내려주고, 상단의 검색 입력(placeholder ‘음식 검색’)이 클라이언트에서 이름 부분 일치로 필터링한다. ‘어느 음식으로 병합할까?’ 라벨은 카드 밖 위에 헤딩 규격으로 둔다(최신 규격은 아래 2026-09-18 문구·간격 추가 정리 참고). 검색 입력과 리스트 사이에도 행 구분선과 같은 회색 선을 둔다. 각 선택지는 카드가 아니라 홈 최근 기록과 같은 행 규격이다 — 한 줄 ‘음식명 (N건)’(예: 두부 (4건), 분류·번호 표기 없음, 음식명은 650 굵기·건수는 회색 보조로 왼쪽 4px 간격), 12px, min-height 48px·패딩 9px 8px·행 사이 회색 구분선, 선택된 행은 테두리 없이 일반 회색 배경(#ececf2)만 쓴다. 필터링해도 선택은 유지되며, 결과가 없으면 ‘검색한 음식이 없어. 다른 이름으로 찾아줘.’를 표시한다. `/move/choices` 검색 엔드포인트와 드롭다운 picker(JS 포함)는 제거했다.
- 등록/수정의 ‘어디에 보관할까?’는 뭐 있지? 상단 위치 필터와 같은 배경색을 사용한다. 선택된 실온/냉장실/냉동실은 각 위치 배경색과 먹색 글자, 미선택은 흰색/회색 테두리다.
- 소비·폐기 후 개별 구매 목록의 처리 취소는 완료 알림 문구 옆 8px 간격으로 표시한다. 밑줄 없는 작은 버튼이며, 알림 내부에 포함되어 ×로 알림을 닫으면 함께 숨겨진다. 보관 상태 탭 옆에는 표시하지 않는다.
- 뭐 있지? 상단 필터는 선택 시 전체=연보라, 실온/냉장실/냉동실=해당 위치 배경+먹색, 종료=WARNING 태그 배경+글자색을 사용한다. 미선택은 흰색/기존 회색 테두리다.
- 공통 액션 버튼의 hover/active에서 배경·글자·테두리를 명시해 기본 보라색 호버가 침범하지 않게 한다. 실제 마우스 호버에서 소비·폐기 색상 및 brightness(.96)를 확인했다. disabled 버튼은 hover 상태에서도 filter:none, transition:0s였다.
- 홈 최근 기록 전체 보기도 공통 cancel-link의 밝기 96% 호버를 사용한다. 음식 카드·검색·액션 버튼의 보라색 배경 호버는 제거했다. 선택 탭과 버튼/링크 키보드 포커스의 primary 색은 별도 규칙이다.

- 수정 및 취소 태그의 명칭이 히스토리와 수량 이력에서 동일하게 렌더링되는지 기존 통합 테스트에 검증을 추가했다.
- 사용자 DB 기록을 수정하지 않고 격리된 테스트 DB에서 검증한다. 이벤트 판정, 날짜, 수량 계산 및 취소 규칙은 변경하지 않는다.
- 수량·재고·음식 이동 통합 테스트와 bootJar가 통과했다. 390px 실제 렌더링에서 홈/히스토리/수량 이력의 태그 전체 크기 36×24.8px 및 세로 중앙 정렬을 확인했다. 테두리 1px 유무에 따른 외곽 크기 차이는 없다.

### 2026-09-16 추가 조정

## 음식 목록·경고·긴 이름

- 홈 WARNING은 흰 배경, #FF4040 테두리, WARNING! 배지 #FFF5F5/#D93636을 사용한다. 기존 정렬로 최대 3개, 제목은 전체 대상 수를 표시한다. 3개 초과면 전체 확인하기로 /inventory?warning=true에 연결한다.
- 음식명 왼쪽·사유 오른쪽 한 줄, 양쪽 말줄임과 전체 접근성 이름을 유지한다. 음식명과 사유는 같은 13px이며(음식명만 굵기 600), 사유 칸은 내용 크기로 잡고 남는 폭을 전부 음식명에 준다(2026-09-18). 기한 경과는 #D93636, 개봉 경과·기한 당일·구분자는 #696B7A다. 판정·날짜 계산은 FoodItem의 공통 규칙을 사용한다.
- 위치·경고 조건은 전체 목록→구매 목록→상세→복귀에서 보존한다. 종료는 경고 필터를 적용하지 않는다.
- 구매 헤더는 공통 높이·최대 3줄, 25px에서 1px씩 최소 16px까지 축소한다. 초과하면 말줄임하며 눌러 12px 전체 이름을 펼치고 다시 눌러 닫는다. Enter/Space/Escape를 지원한다.
- 구매 목록 날짜는 유통기한/소비기한, 구매일/개봉일의 2열이며 날짜 영역만 1pt 축소한다. 왼쪽 열 왼쪽 정렬·오른쪽 열 오른쪽 정렬을 유지한다. (+N일) 초과 표기는 문자열 공백 없이 왼쪽 여백 4px로 띄우고, 구매 목록 카드(stock-dates)에서는 항상 날짜 아래 자체 줄로 표시한다(2026-09-18). 오늘 (+0일), 미래·미입력은 경과 표시하지 않는다.
- 구매 목록에서 경고 아이콘을 제거하고 날짜 경과를 표시하며 상세의 기존 경고 정보는 유지한다. 수량과 단위는 띄어쓰기 없이 표시한다.
- 구매 목록 하단(보관 중 탭, 2026-09-17)은 다른 음식으로 병합/잘못 등록했어 5:5 한 행 → 추가 등록 전폭 한 행 → 전체 목록으로 행 순서다. 종료 탭은 병합/잘못 등록했어 5:5 한 행이다.
- 구매 목록 카드의 선택 체크박스(move-select)는 카드 상단 행(위치 태그)과 수직 중심을 맞춘다(2026-09-17): 체크박스 top을 카드 상단 여백과 일치시킨다 — 보관 중 14px, 종료 카드 12px, 360px 미만 10px(2026-09-18 밀도 축소 반영). 체크박스 박스 높이 26px는 상단 행 최소 높이와 같다.
- 긴 음식명 제목은 3줄에 맞춰 25→16px로 자동 축소한다(food-title.js). 리로드(필터·보관 중/종료 탭 전환 포함) 시 기본 크기로 그렸다가 줄어드는 화면 덜컹임을 막기 위해, head의 한 줄 스크립트가 js-title-fit 클래스로 제목을 숨겨 두고 크기 확정 후 한 번에 표시한다(2026-09-17). JS가 없으면 클래스가 켜지지 않아 제목은 항상 보인다. 대상: 개별 구매 목록·항목, 처리 확인, 수량 분리.
- 체크박스 공통 규격(2026-09-17 사용자 확정): 앱의 모든 체크박스는 19×19px 커스텀 스타일(흰 배경·회색 1px 테두리·모서리 3px) 하나를 쓰고, 체크박스와 뒤따르는 문장 사이 간격은 8px다(필터는 4px에서, 삭제 확인 라벨은 규칙 없음에서 통일). 삭제 확인의 라벨 문장은 버튼 위 문구와 같은 13px다(2026-09-18, 상속 16px 정리). 체크 색은 의미별 2색 — 경고 맥락(확인 필요 필터, 일괄 등록 중복 확인, 삭제 확인의 그룹 동반 삭제)은 경고색 체크+연분홍 배경, 일반 맥락(오늘 넣었어, 목록의 병합/삭제 대상 선택)은 primary 보라 체크+연보라 배경.
- 체크박스 가로 위치는 탭·화면 폭과 무관하게 동일하다(left 14px, 박스 26px). 위치 태그는 항상 카드 왼쪽 기준 48px에서 시작해 체크박스와 태그 사이 간격을 8px로 유지한다 — 상단 행 들여쓰기를 카드 좌측 여백에 맞춰 보정한다(여백 14px→34px, 여백 10px(종료·좁은 화면)→38px). 기준은 보관 중 탭이다(2026-09-17, 2026-09-18 카드 여백 축소 반영).
- 개별 구매 목록의 추가 등록 버튼은 병합/삭제 2열 그리드가 아닌 일반 행에 단독 배치해 전폭을 차지한다(빈 목록의 추가 등록도 동일, 2026-09-17).
- 하단 복귀 링크(전체 목록으로·개별 목록으로·돌아가기)와 바로 위 버튼 사이 간격은 모든 화면에서 10px다(2026-09-18 사용자 요청으로 20px에서 축소 — 복귀 링크 단독 form-actions 행의 상하 여백 10px 제거, merge-submit/목록 버튼의 아래 여백 10px만 남김). merge-submit은 글줄 부산물이 생기지 않도록 블록 배치(display:flex)를 쓰고, 높이는 다른 버튼과 같은 min-height를 따른다(2026-09-17 50px→48px 통일, 2026-09-18 밀도 축소로 공통 44px). 병합 화면 최초 진입(모드 미선택) 시에도 모드 버튼과 돌아가기 사이는 20px이며, 모드 선택 시 열리는 입력 블록과의 간격은 그 블록의 위 여백 20px가 만든다.
- 히스토리는 행 전체 클릭과 기존 이동 목적지를 유지한다. 수정 전후 화살표를 강조하며 동일 값은 수정 이력에서 제외한다.
- 홈 최근 기록의 `전체 보기 →`는 공통 cancel-link 기본·호버 스타일을 사용하고 글자 12px·최소 높이 44px·좌우 padding 8px을 적용한다. `위치별로 보기` 보조 문구는 제거한다. `한눈에 보기` 제목 옆 날짜에만 오른쪽 padding 8px을 적용한다.
- 이동 선택 목록은 필드 너비 안에서 최대 2줄 말줄임, 전체 접근성 이름과 키보드 조작을 유지한다. 최종 음식명은 오른쪽 정렬·좌→우 읽기, 되돌릴 수 없다는 안내는 별도 줄이다.

작업별 UI 보고서나 스크린샷을 커밋하지 않는다. 검증용 파일은 build/reports 아래에 두고 확정 규격은 이 문서를 갱신한다.

## 쪼코 이미지 관리

- 앱에서 사용하는 원본은 src-assets/choco의 77개 이미지다. 원본은 배포 아티팩트(jar)에 포함되지 않으며, 서빙되는 것은 웹용 WebP 사본뿐이다. 일반 헤더 후보는 62개이며 정확한 영역별 풀은 choco-selector.js를 기준으로 한다.
- 영역별 독립 shuffle bag과 화면 내 중복 방지, 프로필 세션 유지, 오류/빈 상태/경고 등 용도별 후보 정책을 유지한다. 입력·리렌더 중 불필요한 재선택을 피한다.
- 원본 PNG·투명도·비율·방향을 보존하며 contain을 사용한다. 원본 파일은 재압축·잘라내기·좌우 반전하지 않는다. 2026-09-17 이미지 로딩 개선 요청에 따라 실제 화면에는 `assets/choco/web/v1/`의 웹용 WebP 사본 77개를 제공한다. 최대 변 660px(최대 220 CSS px 슬롯의 3배), 품질 85, 알파 품질 100이며 `scripts/build-choco-web.py`(Pillow 필요)로 생성한다. 웹용 사본 합계는 4,249,030바이트로 원본 250,838,887바이트 대비 98.3% 감소했다.
- 이미지는 로딩 중에도 공간을 확보하고 다운로드·디코딩이 끝난 뒤 표시한다. 오래된 로딩 결과는 새 이미지 선택에 영향을 주지 않는다. 로드 실패 시 같은 그룹의 대체 후보를 한 번 시도하고 실패하면 자리를 유지한 채 숨긴다. 로그인·계정의 고정 이미지도 웹용 사본과 동일한 표시 방식을 사용한다.
- 운영의 버전 경로 웹용 이미지만 1년 public/immutable 캐시를 사용한다. 사본을 변경할 때는 `v2` 등 새 경로와 로더·고정 이미지 URL을 함께 적용한다. 이미 배포한 버전 경로의 파일을 덮어쓰지 않는다. 로컬 ui-dev는 기존 no-store 정책을 유지한다. 로그인·사용자 데이터에는 이미지 캐시 정책을 적용하지 않는다.
- 브라우저 탭 아이콘은 사용자가 제공한 원본 `scripts/choco-favicon.png`에서 `scripts/build-favicon.py`(Pillow 필요)로 생성한다. 알파 경계로 잘라 정사각으로 맞춘 뒤 `static/favicon.ico`(16/32/48, 투명 유지)와 `static/apple-touch-icon.png`(180px, iOS가 투명을 검정으로 채우므로 흰 배경 합성)를 만든다. 승인된 77개 쪼코 이미지 폴더는 사용·수정하지 않는다. 두 파일은 로그인 없이 접근할 수 있고, 버전 경로가 아니므로 1일 public 캐시만 사용한다. 아이콘을 교체하면 원본을 바꾸고 스크립트를 재실행해 같은 경로에 덮어쓴다.
- 이미지 검증 자료는 src/test/resources/choco의 JSON·CSV에 둔다. 최초 반입/보정 해시와 승인된 14개 교체의 전후 해시 연결을 검증한다. 현재 파일에 맞춰 기대 해시를 임의로 덮어쓰지 않는다.
- 새 이미지 교체는 원본·출처·전후 증거를 확인하고 검증 자료를 함께 갱신한다. 작업 ZIP 설명·접촉표·스크린샷·예비 사진 복사본은 저장소에 중복 보관하지 않는다.

## 참고: 전체·보관 위치·WARNING 색상

현재 CSS 기준의 참고 표다. 전체는 선택된 필터 탭, 실온·냉장실·냉동실은 보관 위치 태그, WARNING!은 홈 경고 배지를 기준으로 한다.

| 태그 | 배경 | 글자 | 테두리 |
| --- | --- | --- | --- |
| 전체 (선택 탭) | #F0E9FF | #30313D | 배경색 1px |
| 실온 | #FFF5CF | #30313D | 없음 |
| 냉장실 | #E3F6EC | #30313D | 없음 |
| 냉동실 | #E5F1FF | #30313D | 없음 |
| WARNING! | #FFF5F5 | #D93636 | 없음 |

- 보관 위치를 필터 탭으로 표시할 때는 선택 상태에 해당 배경색의 1px 테두리를 적용한다. 미선택 탭은 흰색 배경과 #EBEAF1 1px 테두리다.
- 종료 선택 탭은 WARNING!과 같은 배경·글자색을 사용하며 테두리는 배경색 1px이다. 개별 구매 목록의 보관 중 선택 탭은 전체와 같은 색상을 사용한다.
- 홈 보관 위치 카드도 위 배경색을 공유한다. WARNING! 배지에는 테두리가 없지만, 이를 포함한 홈 경고 카드에는 #FF4040 1px 테두리와 흰색 배경을 적용한다.

### 등록 방식과 일괄 등록 — 최종 규격 (2026-09-16)

- 이건 뭐야? 화면은 신규 등록 / 추가 등록 / 일괄 등록을 같은 폭의 한 줄로 배치하며 선택한 입력 영역만 표시한다.
- 일괄 등록은 공통 form-section / section-label을 사용하는 2개 카드로 구성한다.
- 01 “양식에 음식을 적어 업로드해줘”: 엑셀 양식 받기 → 첨부 파일 필수 → `.xlsx 파일 1개(최대 2MB)를 업로드할 수 있어.` → 파일 선택 순이다. 500개 제한은 서버 검증에 유지하고 화면 설명에서는 생략한다.
- 엑셀 양식 받기는 등록 완료와 같은 action-create 스타일이다. 다운로드 영역 하단은 padding 20px, 1px 구분선, margin 20px으로 첨부 영역과 분리한다.
- 파일 1개 선택 시 자동 업로드·검증한다. 미리보기 버튼은 없다. 파일 선택 아래는 진행 상태·검증 오류만 표시한다.
- 완료 후 02 “등록할 음식을 확인해줘”로 스크롤·포커스를 이동한다. 파일을 교체하거나 선택 해제하면 이전 결과를 숨기고 등록 완료를 비활성화한다.
- 하단에는 목록으로 / 등록 완료를 표시한다. 실제 저장은 유효한 결과를 확인한 뒤 등록 완료를 눌러 수행한다. 미선택·오류 상태의 별도 저장 안내는 없다.
- 기존 음식 선택은 엑셀 시트·드롭다운에서 제공한다. 웹 번호 목록과 음식 묶음은 제공하지 않는다.
- 날짜 입력의 연도-월-일 표시는 `calc(16px - 1pt)`다.

- 02 상단은 “상세 정보를 펼치면 확인할 수 있어. 30분 동안 유효해.”와 필요한 오류 안내만 표시한다. 확인 중인 파일·확인 필요 항목 수는 생략하며 파일명은 첨부 영역에서 확인한다.
- 행별 카드는 등록 유형·시트 행 번호·음식명 아래에 오류를 표시한다. 반복 등록 유형과 별도 수량 요약은 표시하지 않는다.
- 누락 필수값은 한 줄의 항목명 목록으로 묶는다. 입력 형식 오류와 누락 오류를 중복 표시하지 않으며 세부 정책은 일괄 등록 문서를 따른다.
- 행 오류는 명시적인 유형·필드를 기준으로 표시한다. 같은 필드의 파생 오류와 잘못된 선택값에 대한 자동 보정 안내를 억제한다. 보관 위치가 미정이면 “냉동실이 아닌 행”으로 단정하지 않는다. 기존 색상·배치·중복 확인 UI는 유지한다.
- 자동 보정 안내는 12px·줄 높이 1.8에 등록 완료 글자색 `--history-create-fg` (#42649A)을 사용한다. 오류와 중복 확인 안내는 오류 색상이다.
- 상세 정보 화살표 왼쪽 margin은 4px, 화살표와 문구 간격은 10px이다. 접힌 상세 정보 아래 여백과 카드 제목 위 여백은 각각 20px이다.
- 상세 정보와 개별 구매 카드 날짜는 2열·각 열 좌측 정렬이다. 항목 내부 라벨 폭은 4.5em, 값과의 간격은 8px, 글자 크기는 `calc(13px - 1pt)`, 줄 높이는 1.5다.
- 일반 라벨은 400, 일괄 등록 필수 항목인 수량·보관 위치 라벨은 700이다. 수량과 단위는 `4장`처럼 붙여 표시한다.

### 중복 확인과 공통 체크박스

- 중복 안내: “같은 내용이 이미 등록된 적 있어서 확인이 필요해.”
- 확인 문구: “새로 구매한 거라서 새 항목으로 추가하는 게 맞아!”
- 두 문구와 체크박스 묶음은 중앙 정렬한다. 12px·줄 높이 1.8·동일한 오류 색상이며 중복 안내 아래 추가 margin과 체크박스 라벨 최소 높이는 없다.
- 중복 확인 체크박스는 14px 고정 폭, 문구와 gap 8px이다. 여러 줄에서도 간격을 유지한다.
- 체크박스가 나오면 “확인한 내용을 저장하려면 등록 완료를 눌러줘.” 안내는 숨긴다. 체크 전 등록 완료는 비활성화, 체크 시 활성화, 해제 시 다시 비활성화한다. 파일 변경 후 이전 확인으로 재활성화하지 않는다.
- 중복 확인·확인 필요 필터·오늘 넣었어 체크박스의 선택 배경은 WARNING 배경색 `#FFF5F5`, 체크 표시·테두리는 WARNING 글자색 `#D93636`이다. 각 체크박스의 기존 크기·문구 간격은 유지한다.

### 개별 구매 목록

- “정보를 확인하고 수정할 수 있어.” 안내는 제거한다. 보관 중·종료 탭과 같은 줄 오른쪽 끝에 확인 필요 필터를 둔다. 종료 탭에서는 필터를 표시하지 않는다.
- 확인 필요 필터 결과가 비어 있으면 빈 상태와 전체 목록으로를 표시하며 다른 음식으로 병합·추가 등록 버튼은 숨긴다.
- 유통기한·소비기한·구매일·개봉일은 일괄 등록 상세 정보와 같은 라벨·값 정렬을 사용하며 경고 색과 경과 일수는 유지한다.

- 로그인 전 상단 헤더의 프로필 영역은 숨긴다. 로그인 사용자 닉네임·프로필 사진 기능은 운영 후 최하위 우선순위로 미룬다.

- 로그인·내 프로필·접근 거부·일반 오류의 상단은 shell의 accessHeading을 공유한다. 공통 tab-heading/tab-sheet 여백과 쪼코 영역을 유지하며 오류 설명은 닫을 수 없는 본문 문구로 유지한다. 접근 오류 설명은 명시적인 줄바꿈으로 두 문장을 구분한다. 복귀 버튼은 form-actions의 전체 너비를 사용한다. 비로그인 오류 화면은 프로필·하단 메뉴를 숨긴다.

- 요청 확인 실패·404·일반 오류는 상단 문구(에엥;;;; / 이게 뭐지? / 🚨오류 발생🚨)를 통일하고 본문 설명을 가운데 정렬한다. 본문 위 여백은 공통 tab-sheet padding-top 24px, 아래는 access-error-message margin-bottom 20px와 form-actions padding-top 10px를 공유한다.

- 오류 3종의 버튼 위 설명은 공통 카드 테두리(1px var(--line), 모서리 20px, 흰 배경, 안쪽 여백 20px 16px)를 사용한다. 가운데 정렬·명시적 줄바꿈을 유지하며 닫기 기능은 없다.

- 오류 화면은 error.html 한 파일에서 관리한다. /access-denied는 보안 요청 거부 표시를 전달하고 HTTP 403으로 같은 템플릿을 렌더링한다. 403·404·기타 오류별 두 문장과 복귀 링크만 분기한다. 인증 필요는 로그인 이동, 비밀번호 불일치는 로그인 폼 내 오류로 구분한다.

- 오류 메시지 알림은 notice notice-error를 사용한다. 공통 알림의 폰트·여백·모서리·닫기 동작을 유지하고 WARNING 태그의 배경 var(--warning-expired-bg) (#FFF5F5)와 글자색 var(--warning-text) (#D93636)을 1px 테두리에 적용한다. 이를 공통 오류 전용 알림 양식으로 사용한다. 로그인 실패에 적용하며 기존 오류 요약 양식은 별도로 유지한다.

- 히스토리의 첫 기록 위에도 하단과 같은 1px var(--line) 구분선을 적용한다. 빈 기록 화면에는 선을 추가하지 않는다.

- 빈 상태 카드의 상하 안쪽 여백은 공통 28px로 유지한다. 하단 portrait 쪼코에도 하단 여백을 없애지 않는다. 히스토리는 버튼→하단 이미지 20px, 재고·개별 구매 빈 상태는 기존 16px 간격을 유지한다.
