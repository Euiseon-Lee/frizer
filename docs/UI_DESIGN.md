- FoodActionType.label()을 공통 명칭으로 사용한다. 수량 이력의 ‘정정’은 ‘수정’, 히스토리 태그의 ‘처리 취소’는 ‘취소’로 통일한다. ‘처리 취소’ 버튼 문구와 동작은 유지한다.
- 음식 간 이동과 음식 통합 이동(MERGE)은 모두 ‘이동’ 태그와 동일한 색상을 사용한다. 저장된 이벤트 종류는 변경하지 않는다.
- 모든 화면에서 action-badge history-badge와 data-event를 사용한다. 별도 수량 이력 색상 및 화면별 크기 덮어쓰기를 제거한다.
- 글자 12px, 굵기 400, 행간 1.4, 둥근 모서리 6px. 등록부터 이동까지 모든 액션 태그에 글자색 1px 테두리와 세로 3px/가로 5px 여백을 적용한다.
- border-box로 전체 너비/높이를 명시한다. 기본 글자 크기에서 전체 36×24.8px이며, 테두리 있는 태그의 안쪽 공간만 가로/세로 2px 줄어든다.
- 위치 태그, 보관 위치 카드, WARNING!, primary 색상은 변경하지 않는다. 액션 색상은 독립된 history 토큰으로 관리한다.
- 모든 액션·위치 태그는 소속 행에서 세로 중앙 정렬한다. 히스토리 탭의 별도 여백 및 크기 설정을 제거했다.
- 먹었어/버렸어 버튼은 소비/폐기 태그의 배경·글자색을 공유한다. 다른 음식으로 이동/수정 버튼도 해당 태그 색상을 공유한다. 모든 액션 버튼 테두리는 각 태그 글자색의 1px로 통일한다.
- 수량 이력의 작은 처리 취소 버튼은 예외적으로 기존 스타일을 유지한다. 테두리 없음/연회색 배경/회색 글자이며 호버 시 공통 밝기 96%를 사용한다. 취소 태그 색상과 연결하지 않는다.
- 이동/수정/먹었어/버렸어 버튼은 호버와 눌림에서 현재 색상에 brightness(.96)를 적용한다. 이동 버튼의 기존 보라색 호버보다 높은 우선순위로 새 배경·글자·테두리 색상을 유지한다.
- 홈 ‘음식 등록하러 갈까?’와 개별 구매 목록 ‘기존 음식에 추가’는 등록 색상과 글자색 테두리를 사용한다. 홈 버튼 오른쪽 여백은 4px이다.
- 이건 뭐야 탭의 등록/기존 음식에 추가 제출 버튼은 등록 색상, 수정 제출 버튼은 수정 색상을 사용한다. 수정 제출 문구는 ‘수정 완료’다.
- 신규 등록·기존 음식에 추가 두 탭의 제출 문구는 모두 ‘등록 완료’로 통일한다. 탭 전환 시 JavaScript도 같은 문구를 유지한다. 개별 구매 목록의 진입 버튼 ‘기존 음식에 추가’는 유지한다.
- 버렸어 버튼도 최신 지시에 따라 폐기 태그 글자색의 1px 테두리를 적용한다.
- 비활성화 버튼은 hover/active 색상과 밝기 효과를 적용하지 않는다. 해당 선택자를 :not(:disabled)로 제한하고 disabled의 filter/transition을 제거한다.
- 등록/수정 화면의 01·02·03 단계 번호 배경은 취소 링크 호버와 공통인 --subtle-hover-bg (#F7F7FB)를 사용한다. 글자색·여백은 유지한다.
- 실온/냉장실/냉동실 및 WARNING! 태그에는 테두리를 추가하지 않는다. 비교표의 공통 테두리 규칙이 위치·경고 색상 견본에도 적용된 오류만 수정했다. 실제 앱의 해당 태그는 원래부터 테두리가 없었다. WARNING 카드 외곽 테두리는 유지한다.
- 2026-09-16 후속 파스텔 조합을 적용했다. 7개 액션의 글자 대비는 약 5.00~6.19:1이다. 기존 테두리 유무·크기·호버 효과는 유지하며 연결된 버튼도 공통 토큰을 통해 함께 변경된다.

## 검증

- 검색 버튼(기존 음식에 추가/음식 이동)은 공통 search-button으로 통일한다. 기본 배경 #F7F7FB, 글자 및 1px 테두리 #696B7A, 호버 밝기 96%. 기본 보라색 버튼 규칙에서 분리했다. 이전 보라색 호버 조사 결과 중 검색 버튼은 해소됐다.
- 기존 음식 선택 후 요약 영역과 긴 음식명 펼침 영역은 #F7F7FB 공통 토큰을 사용한다. 변경 버튼은 연회색 배경/회색 글자와 테두리, 밝기 96% 호버로 바꾸며 기존 크기·모서리·여백을 유지한다.

- 필수 표기는 WARNING 글자색 #D93636을 사용한다.
- 등록 방식 선택은 미선택 흰색/회색 테두리, 선택 배경 #42649A/글자 #EDF3FF/테두리 #42649A다.
- 음식 이동하기의 기존 음식으로 이동/새로운 음식으로 변경 선택은 미선택 흰색/회색 테두리, 선택 배경 #596344/글자 #FFF6D8/테두리 #596344다.
- 등록/수정의 ‘어디에 보관할까?’는 뭐 있지? 상단 위치 필터와 같은 배경색을 사용한다. 선택된 실온/냉장실/냉동실은 각 위치 배경색과 먹색 글자, 미선택은 흰색/회색 테두리다.
- 소비·폐기 후 개별 구매 목록의 처리 취소는 완료 알림 문구 옆 8px 간격으로 표시한다. 밑줄 없이 문구 높이에 맞춘 작은 버튼이며, 알림 내부에 포함되어 ×로 알림을 닫으면 함께 숨겨진다. 보관 상태 탭 옆에는 표시하지 않는다.
- 뭐 있지? 상단 필터는 선택 시 전체=연보라, 실온/냉장실/냉동실=해당 위치 배경+먹색, 종료=WARNING 태그 배경+글자색을 사용한다. 미선택은 흰색/기존 회색 테두리다.
- 공통 액션 버튼의 hover/active에서 배경·글자·테두리를 명시해 기본 보라색 호버가 침범하지 않게 한다. 실제 마우스 호버에서 소비·폐기 색상 및 brightness(.96)를 확인했다. disabled 버튼은 hover 상태에서도 filter:none, transition:0s였다.
- 남은 보라색 호버는 홈 최근 기록 전체 보기의 글자색이다. 음식 카드·검색·액션 버튼의 보라색 배경 호버는 제거했다. 선택 탭과 버튼/링크 키보드 포커스의 primary 색은 별도 규칙이다.

- 수정 및 취소 태그의 명칭이 히스토리와 수량 이력에서 동일하게 렌더링되는지 기존 통합 테스트에 검증을 추가했다.
- 사용자 DB 기록을 수정하지 않고 격리된 테스트 DB에서 검증한다. 이벤트 판정, 날짜, 수량 계산 및 취소 규칙은 변경하지 않는다.
- 수량·재고·음식 이동 통합 테스트와 bootJar가 통과했다. 390px 실제 렌더링에서 홈/히스토리/수량 이력의 태그 전체 크기 36×24.8px 및 세로 중앙 정렬을 확인했다. 테두리 1px 유무에 따른 외곽 크기 차이는 없다.

### 2026-09-16 추가 조정
- 최근 기록·히스토리 CANCEL 태그는 `취소`, 버튼은 `처리 취소`로 구분한다. 공통 Java 명칭 FoodActionType.label()만 사용한다. 사용자 확인에 따라 재시작 전 서버를 위한 템플릿 예외 처리는 두지 않으며 앱 재시작 후 취소로 반영된다.
- 구매 완료 알림 배경은 공통 연회색 `#F7F7FB`를 사용한다.
- 버튼 호버는 `--button-hover-brightness: .96`으로 통일하고 비활성 버튼은 제외한다. 중립 버튼은 기존 호버 연회색을 기본 배경으로 사용한다.
- 버튼은 행 안에서 align-self:center, 내부 문구는 inline-flex 중앙 정렬을 사용한다.
- 음식 카드 호버는 연회색 배경과 먹색 테두리, 키보드 포커스도 먹색 윤곽선을 사용한다.

- 공통 input/select/textarea 포커스는 먹색 #30313D 2px, outline-offset -2px로 고정한다. 오류 필드는 #D93636을 유지한다. 라디오 선택 UI 및 버튼/링크 포커스는 별도 규칙으로 유지한다.
- 개별 구매 목록의 보관 중/종료 탭은 뭐 있지?의 전체/종료와 같은 선택 색상 규칙을 공유한다. 보관 중 #F0E9FF/#30313D, 종료 #FFF5F5/#D93636, 미선택 흰색/회색 테두리다.

## 음식 목록·경고·긴 이름

- 홈 WARNING은 흰 배경, #FF4040 테두리, WARNING! 배지 #FFF5F5/#D93636을 사용한다. 기존 정렬로 최대 3개, 제목은 전체 대상 수를 표시한다. 3개 초과면 전체 확인하기로 /inventory?warning=true에 연결한다.
- 음식명 왼쪽·사유 오른쪽 한 줄, 양쪽 말줄임과 전체 접근성 이름을 유지한다. 기한 경과는 #D93636, 개봉 경과·기한 당일·구분자는 #696B7A다. 판정·날짜 계산은 FoodItem의 공통 규칙을 사용한다.
- 위치·경고 조건은 전체 목록→구매 목록→상세→복귀에서 보존한다. 종료는 경고 필터를 적용하지 않는다.
- 구매 헤더는 공통 높이·최대 3줄, 25px에서 1px씩 최소 16px까지 축소한다. 초과하면 말줄임하며 눌러 12px 전체 이름을 펼치고 다시 눌러 닫는다. Enter/Space/Escape를 지원한다.
- 구매 목록 날짜는 유통기한/소비기한, 구매일/개봉일의 2열이며 날짜 영역만 1pt 축소한다. 왼쪽 열 왼쪽 정렬·오른쪽 열 오른쪽 정렬, 날짜와 (+N일) 사이 공백 한 칸을 유지한다. 오늘 (+0일), 미래·미입력은 경과 표시하지 않는다.
- 구매 목록에서 경고 아이콘을 제거하고 날짜 경과를 표시하며 상세의 기존 경고 정보는 유지한다. 수량과 단위는 띄어쓰기 없이 표시한다.
- 구매 목록 하단은 다른 음식으로 이동/기존 음식에 추가 5:5, 전체 목록으로는 다음 행 전체 너비다.
- 히스토리는 행 전체 클릭과 기존 이동 목적지를 유지한다. 수정 전후 화살표를 강조하며 동일 값은 수정 이력에서 제외한다.
- 이동 선택 목록은 필드 너비 안에서 최대 2줄 말줄임, 전체 접근성 이름과 키보드 조작을 유지한다. 최종 음식명은 오른쪽 정렬·좌→우 읽기, 되돌릴 수 없다는 안내는 별도 줄이다.

## 문서·미리보기 관리

작업별 UI 보고서나 스크린샷을 커밋하지 않는다. 검증용 파일은 build/reports 아래에 두고 확정 규격은 이 문서를 갱신한다.

## 쪼코 이미지 관리

- 앱에서 사용하는 원본은 src/main/resources/static/assets/choco의 77개 이미지다. 일반 헤더 후보는 62개이며 정확한 영역별 풀은 choco-selector.js를 기준으로 한다.
- 영역별 독립 shuffle bag과 화면 내 중복 방지, 프로필 세션 유지, 오류/빈 상태/경고 등 용도별 후보 정책을 유지한다. 입력·리렌더 중 불필요한 재선택을 피한다.
- 원본 PNG·투명도·비율·방향을 유지하며 contain을 사용한다. 좌우 반전이나 임의 재압축·잘라내기를 하지 않는다. 로드 실패 시 같은 그룹의 대체 후보를 한 번 시도하고 실패하면 자리를 유지한 채 숨긴다.
- 이미지 검증 자료는 src/test/resources/choco의 JSON·CSV에 둔다. 최초 반입/보정 해시와 승인된 14개 교체의 전후 해시 연결을 검증한다. 현재 파일에 맞춰 기대 해시를 임의로 덮어쓰지 않는다.
- 새 이미지 교체는 원본·출처·전후 증거를 확인하고 검증 자료를 함께 갱신한다. 작업 ZIP 설명·접촉표·스크린샷·예비 사진 복사본은 저장소에 중복 보관하지 않는다.
