# Codex 전달 지시서 — 쪼코 UI 이미지 패키지 V3

## 시작
이 폴더는 쪼코를 활용하는 냉장고 재고관리 웹의 이미지 패키지다. README.md, ASSET_MAPPING.md, asset-map.json을 읽고 25개 PNG를 직접 확인한 뒤 기존 프로젝트에 적용하라. 예전 IMG_* 파일 및 앞선 사진 매핑은 이 패키지로 대체한다. 아래 경로는 ZIP 해제 폴더 기준이며 다른 대화의 /workspace/scratch 경로를 사용하지 않는다.
기존 UI 개편 지시서와 함께 제공될 경우 이미지 이름·역할은 본 패키지를 우선한다. 기존 프로젝트의 요구사항·API 계약·도메인 규칙을 우선하고, 이전 제안으로부터 새로운 정책을 임의 확정하지 않는다.

## 구현 순서
1. 프로젝트의 AGENTS.md 및 프레임워크·라우팅·이미지 처리·기존 API를 확인한다.
2. assets/choco/*.png를 프레임워크에 맞는 정적 자산 디렉터리로 복사한다. React/Vite 등의 public/assets/choco, Spring의 src/main/resources/static/assets/choco는 예시이며 강제 경로가 아니다.
3. asset-map.json은 전달 자산 명세다. path는 패키지 상대경로이므로 실제 런타임 URL과 구분한다. 웹 URL에 public/ 또는 src/main/resources/static/을 그대로 넣지 않는다.
4. 먼저 home-hero, profile, add-food로 기본 화면을 구성하고 상태에 따라 success, attention, empty-curious, rest, sniff를 사용한다. playful은 선택 사항이다. 25장 풀에서 화면·상태에 맞는 사진을 다양하게 사용한다.
5. 원본 얼굴과 표정을 보존한다. 가짜 사진이나 새 강아지 이미지로 대체하지 않는다. 누끼 경계·잔디·손은 현재 남아 있다. 필요한 보정은 원본 보존 후 별도 파생본에 적용한다. 형식 변환만으로 배경 제거·테두리 정리가 된다고 가정하지 않는다.
6. 알파를 유지하고 object-fit: contain을 사용한다. 의도적인 프로필 마스크 외에는 얼굴·귀·코를 자르지 않는다. 화면 크기에 맞춘 파생 WebP를 만들 수 있지만 원본보다 확대하지 않는다. 작은 이미지는 지연 로딩하고 히어로는 우선 표시한다. 이미지 크기를 지정해 레이아웃 이동을 방지한다.

## 디자인 방향
참고 https://saju-kid.com/ 의 분위기와 배치 원리를 활용한다. 사진·문구·로고를 복제하지 않는다.
- 데스크톱 중앙 최대 약 448px, 모바일 전체 너비. 기존 앱이 더 넓은 레이아웃을 요구하면 구조를 먼저 검토.
- 따뜻한 크림 바탕, 흰 카드, 파스텔 보관 위치 색상, 둥근 모서리 18~20px.
- 좌우 여백 16px, 카드 간격 8~12px. 상단 헤더 48~56px.
- 히어로 약 200~260px: 짧은 안내와 오른쪽 아래 home-hero. 이미지와 문구가 겹치면 높이나 배치 조정.
- 메인 콘텐츠 상단 라운드 28~32px. 필요 시 히어로와 약간 겹침.
- 홈 구성: 오늘 요약 → 소비기한 경과 별도 안내 → 오늘 먼저 확인할 음식 TOP 3 → 보관 위치 요약 → 최근 기록. 음식 등록은 쉽게 접근 가능하게 배치.
- 보관 위치는 냉장·냉동·실온·전체 2열 요약 카드. 데이터가 많은 실제 음식 목록은 읽기 쉬운 목록형.
- 하단은 홈/음식/추가/기록 캡슐형 내비게이션. 아이콘과 라벨을 함께 사용. 추가는 등록 진입 동작이며 페이지 탭과 구분 가능.
- 하단 safe-area와 고정 내비 높이를 반영해 콘텐츠 가림 방지.
- 사용자는 쪼코가 많이 등장하기를 명시적으로 원한다. 큰 대표 사진과 여러 작은 사진을 함께 배치하고 보관 위치 카드에도 서로 다른 쪼코 사진을 사용한다. 이미지 수를 1개로 제한하지 않는다. 아래 V3 배치 규칙을 우선한다.

## 색상 출발점
크림 #FFF8ED, 표면 #FFFFFF, 바깥 배경 #F5F5F3, 캐러멜 #C78B52, 진한 갈색 #594135, 본문 #292522, 보조 글자 #766E67, 냉장 민트 #DDF2E6, 냉동 파랑 #DDEEFF, 실온 크림 #F9EDCE, 주의 배경 #FFF0E5, 주의 글자 #B85C38.
색은 출발점이다. 밝은 캐러멜 위 흰 글씨는 대비를 검증하고 필요하면 버튼을 어둡게 하거나 짙은 글씨를 사용한다. 상태를 색만으로 전달하지 않는다.

## 캐릭터와 문구
쪼코는 호기심 있고 장난기 있는 냉장고 지킴이. 이것은 UI 캐릭터 설정이며 실제 성격의 단정이 아니다.
짧고 자연스러운 반말. '킁킁'은 인사·새 음식 발견에 가끔 사용. 모든 문장에 '~멍' 또는 '~냥'을 붙이지 않는다. 사용자를 혼내거나 폐기에 죄책감을 주지 않는다.
- 홈: '쪼코가 냉장고를 살펴봤어.' / '오늘 먼저 확인할 음식이 3개 있어.'
- 등록: '킁킁, 새 음식이 왔네!' / 버튼 '음식 등록하기'
- 성공: 실제 저장 성공 후 '등록했어!' 또는 '소비한 걸로 기록했어.'
- 빈 목록: '아직 등록된 음식이 없어. 첫 음식을 등록해볼까?'
- 임박 없음: 조회 성공 시에만 '오늘 먼저 확인할 음식은 없어.'
- 로딩: 실제 요청 중에만 '음식 목록을 불러오는 중이야…'
- 오류: '지금은 불러오지 못했어. 다시 시도해줘.' / '다시 시도'
버튼은 등록하기, 소비하기, 폐기하기, 이동하기, 취소처럼 실행 결과가 명확하게 보이도록 쓴다.
시스템은 등록된 데이터로 표시한다. 냄새·사진으로 신선도나 섭취 안전을 판단하는 기능이 있다는 인상을 주지 않는다. '냄새가 괜찮으니 먹어도 돼', '오래된 음식을 냉동하면 안전해' 같은 문구 금지.
소비기한 경과 표시는 '소비기한 경과 — 확인 필요'처럼 사실을 명확히 보여주며 먹도록 유도하지 않는다. 이전 지시서의 '상태를 확인한 뒤 소비하거나 폐기해줘' 문구는 사용하지 않는다.
제품 UI에 'V1' 같은 개발 버전 용어를 노출하지 않는다. 복원 미지원이면 '처리 후에는 되돌릴 수 없어.'라고 안내한다.

## 도메인 연결 범위
현재 구현을 확인한다. UI 제안만으로 냉동 30일 같은 임의 임계값·TOP3 정렬·부분 소비 규칙을 새로 만들지 않는다. 필요한 규칙이 없으면 누락으로 보고한다.
앞서 논의된 목표: 경과 음식은 TOP3와 분리; CREATE/CONSUME/FREEZE/MOVE/DISCARD 이력; 타 위치에서 냉동실 진입은 FREEZE, 냉동실에서 나갈 때는 MOVE; 소비/폐기 상태 변경 및 실행 전 확인; 복원은 기존 요구사항에 따름.
냉동일 입력의 의미는 '우리 집 냉동 보관 시작일'. 모르는 경우 오늘을 제안하되 수정 가능하게 하고 실제 과거 날짜인 것처럼 숨겨 확정하지 않는다.
이력은 당시 행동·시각·보관 위치·수량을 보여주고 음식명은 현재 이름을 쓴다는 앞선 제안과 현재 모델의 일치 여부를 확인한다. 이 패키지는 DB 변경 지시가 아니다.

## 검증과 보고
320/375/390/448px 및 데스크톱에서 가로 넘침, 긴 이름, 빈 목록, 로딩, 오류, 경과 데이터, 내비 가림, 이미지 실패를 확인한다. 탭 이동·포커스·다이얼로그 접근성, 44px 이상 터치 영역을 확인한다. reduced-motion을 존중하고 불필요한 무한 애니메이션 금지.
빌드 및 변경 위험에 필요한 핵심 검증을 수행하고 변경 화면·컴포넌트·사진 경로·확인 결과·미완료 보정 사항을 보고한다. 실제 구현하지 않은 보정·업로드·배포를 완료라고 보고하지 않는다.


## V3 최우선 변경 — 쪼코가 자주 등장하는 서비스
이전 지시서의 '사진은 9장', '기능 카드마다 쪼코를 넣지 않는다', '쪼코는 상태 화면에만 제한' 규칙을 폐기한다. 사용자는 사진 다양성과 빈번한 등장을 선호한다. 대표 이미지 1개와 보조 이미지 여러 개의 크기 차이로 정보 가독성을 유지한다.

### 배치 기준과 사진 풀
- 홈: 히어로 1장(140~200px), 4개 보관 위치 카드 각각 서로 다른 작은 사진(56~88px), 등록 배너 1장(72~104px). 세로 스크롤 홈 전체에 약 6~8회 등장 가능. 한 화면에 여러 장을 함께 보여도 좋다.
- 히어로 풀: home-hero / happy-lounge / happy-sit / welcome-lounge. 가로형과 세로형을 동일 CSS에 억지로 넣지 말고 키별 object-position 또는 배치 변형을 지정.
- 냉장실 카드: leaf-hat-front / leaf-hat-side / flower-sniff.
- 냉동실 카드: happy-lounge / rest. 추워 보인다고 사진에 의미를 단정하지 말고 카드의 명시적 제목·파란 배경·눈송이 아이콘으로 위치 전달.
- 실온 카드: proud-sit / happy-sit.
- 전체 음식 카드: profile / happy-closeup.
- 음식 등록: add-food / come-running / flower-sniff. 완료 시 success / happy-sit / gentle-pet.
- 기록: look-back / look-aside. 각 기록마다 큰 사진을 반복하지 않고 날짜 섹션이나 헤더에 작은 사진을 붙인다.
- 처음 사용·재고 없음: puppy-sit / empty-curious. 필터 결과 없음은 등록된 음식 없음과 문구를 구분.
- 도움말·설정: relaxed-stretch / gentle-pet / cheek-squish.
- 로딩: sniff. 정상·임박 없음: rest. 오류: empty-curious + 명확한 오류 텍스트. 경과 안내: attention + 별도 상태 문구, 장난스러운 효과 금지.
- 작은 재미 요소: playful / peek-upside-down. 빈 모서리나 도움말 배너에만 배치하며 버튼·음식명·날짜를 덮지 않는다.

### 교체 방식
사진 풀을 중앙 설정으로 관리한다. 화면별 선택은 최초 진입 시 정하고 해당 화면에서 입력·수량 변경·리렌더가 일어날 때는 유지한다. 다음 방문이나 날짜 변경 시 교체 가능. 타이머 자동 슬라이드 금지. 자동 교체가 인지 부담을 주면 사진을 탭해서 바꾸기 같은 선택적 동작을 제공하되 주요 버튼 클릭과 충돌하지 않게 한다.
대표 로고/정체성의 profile은 기본 고정, 별도 안내 얼굴은 happy-closeup 등 교체 가능. 같은 뷰포트에 동일 사진 반복은 피한다. 25장을 무작정 전부 선로딩하지 말고 필요한 파생 이미지만 요청한다.

### 사진과 문구 연결
leaf-hat: '킁킁, 냉장실에는 뭐가 있을까?'
come-running: '새 음식이 왔네! 같이 등록하자.'
look-back: '우리가 남긴 기록을 볼까?'
puppy-sit: '우리 냉장고에 뭐가 있는지 알려줘.'
rest: '먼저 확인할 음식은 없어.' — 조회 성공·해당 조건 확인 시만 사용.
상태 숫자는 실제 데이터에서 계산한다. 캐릭터 대사는 기계적으로 랜덤 조합하지 말고 상황을 기준으로 선택한다.

### 확인 기준 추가
홈 및 음식/등록/기록/설정·도움말(존재하는 화면)에 쪼코가 나타나는지 확인한다. 사진 개수를 줄이는 대신 작은 화면에서 카드 높이·텍스트 영역·이미지 크기를 조정한다. 사진 풀별 후보를 확인하고 모든 사진을 반드시 같은 비중으로 사용하지는 않는다. 25장 사용 가능 목록과 실제 연결한 화면을 보고한다.
