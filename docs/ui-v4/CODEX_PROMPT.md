# Codex 구현 지시서 V4 — 전체 재검수 / 잔디 제외
이 패키지는 V2/V3 사진 매핑과 교체 후보를 완전히 대체한다. ASSET_MAPPING.md, asset-map.json, image-pools.json을 읽고 실제 사진을 확인한다. 다른 대화의 임시 경로를 사용하지 않는다.

## 적용 우선순위
1. 잔디 사진은 전부 사용 금지. 예전 home-hero, look-back, add-food를 소스에서 제거하고 fallback/사전로딩/랜덤 풀에서도 제외한다. 원본 업로드를 삭제하라는 뜻은 아니다.
2. assets/choco에는 A 우선 사진만 있다. 실제 앱으로 복사할 기본 대상이다.
3. reserve/choco에는 B 후순위 사진이 있다. 이 폴더를 통째로 public에 복사하거나 자동 교체 풀에 등록하지 않는다. 매핑의 특정 배치 조건을 충족하는 작은 보조 이미지로 사용할 수 있다. 큰 히어로/전신으로 승격하려면 사용자에게 파일 ID와 미리보기를 보여 확인한다.
4. 기본 히어로는 happy-lounge. happy-sit/proud-sit를 교체 후보로 사용. 옛 home-hero.png 이름으로 단순 덮어쓰기하지 말고 실제 키·경로를 바꾼다.
5. 원본에 없거나 잘린 발/꼬리/귀를 생성하지 않는다. contain과 외부 여백은 추가 절단을 막지만 원본 절단을 복구하지 못한다.
6. 자연스러운 목·상반신 초상은 카드 하단/가장자리로 배치 가능. 독립된 전신 스티커처럼 공중에 띄우지 않는다.

## 쪼코를 많이 보여주는 원칙 유지
홈 전체 스크롤에서 대표 1장 + 보관 위치별 4장 + 등록 배너 등 약 6~8회 등장 가능. 여러 작은 사진이 동시에 보여도 된다. 사진 수를 제한하기보다 크기·여백·텍스트 영역을 조절한다.
홈 히어로 140~200px, 카드 사진 56~88px, 등록 배너 72~104px는 출발점. 레이아웃별 실제 비율에 맞춰 조정한다. 이미지가 숫자/날짜/버튼을 가리지 않게 한다.
image-pools.json을 기준으로 A에서 화면별 다양성을 확보한다. 사진은 진입 시 선택 후 입력·수량 변경·리렌더 중 유지. 다음 방문 교체 가능, 무한 자동 슬라이드 금지. 37장을 전부 선로딩하지 않는다.
B에서 개성 있는 사진을 활용할 때는 명시된 조건만 적용한다. 예: ice-pack은 귀와 아래 다리 절단 때문에 냉동실의 작은 프레임형 초상 후보이며 기본 풀에는 없음. pillow-rest/long-lounge는 꼬리·앞발 절단으로 큰 배너에 자동 사용 금지.

## 프로젝트 연결
AGENTS.md와 기술 스택, 라우트, 기존 API를 확인하고 도메인 계약을 보존한다. 패키지 경로는 ZIP 기준 상대경로다. 프레임워크에 맞게 public/assets/choco 또는 Spring static 등으로 연결한다. PNG의 투명도 보존, 고정 비율 강제 변형 금지. WebP 파생본 최적화는 별도 작업이며 이 패키지는 리터칭/압축 완료본이 아니다.

## 디자인 방향
참고 https://saju-kid.com/ 의 분위기와 배치 원리를 활용한다. 사진·문구·로고를 복제하지 않는다.
- 데스크톱 중앙 최대 약 448px, 모바일 전체 너비. 기존 앱이 더 넓은 레이아웃을 요구하면 구조를 먼저 검토.
- 흰 바탕, 밝은 파스텔 카드, 통일된 먹색 글씨, 둥근 모서리 18~20px.
- 좌우 여백 16px, 카드 간격 8~12px. 상단 헤더 48~56px.
- 메인 콘텐츠 상단 라운드 28~32px. 필요 시 히어로와 약간 겹침.
- 홈 구성: 오늘 요약 → 소비기한 경과 별도 안내 → 오늘 먼저 확인할 음식 TOP 3 → 보관 위치 요약 → 최근 기록. 음식 등록은 쉽게 접근 가능하게 배치.
- 보관 위치는 냉장·냉동·실온·전체 2열 요약 카드. 데이터가 많은 실제 음식 목록은 읽기 쉬운 목록형.
- 하단은 홈/음식/추가/기록 캡슐형 내비게이션. 아이콘과 라벨을 함께 사용. 추가는 등록 진입 동작이며 페이지 탭과 구분 가능.
- 하단 safe-area와 고정 내비 높이를 반영해 콘텐츠 가림 방지.

## 최종 색상 지시 — 밝은 파스텔 / 갈색 중심 지시 대체
사용자는 현재 화면의 황토·갈색 글씨, 갈색 버튼, 베이지 배너를 촌스럽게 느낀다고 명시했다. 쪼코 털색을 UI 브랜드 색으로 반복하지 않는다. 배경은 밝은 파스텔, 텍스트는 통일된 먹색, 핵심 행동은 보라색 포인트로 구성한다.
- 바깥 배경 #F7F7FB, 콘텐츠 표면 #FFFFFF
- 실온 카드 #FFF5CF (밝은 버터 옐로)
- 냉장실 카드 #E3F6EC (민트)
- 냉동실 카드 #E5F1FF (하늘색)
- 전체 음식 카드 #F0E9FF (라일락)
- 음식 등록 배너 #FFF0F5 (옅은 핑크)
- 모든 카드 제목/수치 공통 #30313D, 보조 글씨 #696B7A
- 주요 버튼 #7057C8, 버튼 글자 #FFFFFF. hover #6048B5
- 경계선 #EBEAF1
카드별 황토/청록/파랑/보라 본문 글씨를 제거한다. 위치 구분은 배경색·아이콘 형태·제목으로 전달한다. 강한 색은 주요 버튼과 실제 경고에 한정한다.
갈색 버튼/캐러멜 포인트/넓은 베이지 배경을 기본 테마에서 제거한다. 경고 색은 일반 장식과 분리한다.
현재 사진의 갈색 털은 그대로 유지한다. 사진 자체를 파스텔 필터로 변색하지 않는다. 그림자는 약하게, 테두리는 얇게; 그라데이션을 추가하여 문제를 덮지 않는다.
글꼴은 프로젝트에 있는 현대적인 한글 산세리프를 우선, 본문 14~16px/줄간격 1.4~1.6, 제목 weight 600~700. 작은 설명의 과한 자간과 지나치게 굵은 숫자를 피한다. 숫자와 제목의 색을 통일해 사진과 경쟁하지 않게 한다.
320/390/448px에서 실제 대비·텍스트 크기를 검증한다. 특히 파스텔색 버튼 위 흰 글씨를 쓰기 위해 대비를 낮추지 않는다. 이 색상 규칙이 이전 크림·캐러멜·진한 갈색 팔레트보다 우선한다.

## 캐릭터와 문구
쪼코는 호기심 있고 장난기 있는 냉장고 지킴이. 이것은 UI 캐릭터 설정이며 실제 성격의 단정이 아니다.
짧고 자연스러운 반말. '킁킁'은 인사·새 음식 발견에 가끔 사용. 모든 문장에 '~멍' 또는 '~냥'을 붙이지 않는다. 사용자를 혼내거나 폐기에 죄책감을 주지 않는다.
- 홈: '쪼코가 냉장고를 살펴봤어.' / '오늘 먼저 확인할 음식이 3개 있어.'
- 등록: '킁킁, 새 음식이 왔네!' / 버튼 '음식 등록하기'
- 성공: 실제 저장 성공 후 '등록했어!' 또는 '소비한 걸로 기록했어.'
- 빈 목록: '아직 등록된 음식이 없어. 첫 음식을 등록해볼까?'
- 임박 없음: 조회 성공 시에만 '오늘 먼저 확인할 음식은 없어.'
- 로딩: 실제 요청 중에만 '음식 목록을 불러오는 중이야…'
- 오류: '지금은 불러오지 못했어. 다시 시도해줘.' / '다시 시도'
버튼은 등록하기, 소비하기, 폐기하기, 이동하기, 취소처럼 실행 결과가 명확하게 보이도록 쓴다.
시스템은 등록된 데이터로 표시한다. 냄새·사진으로 신선도나 섭취 안전을 판단하는 기능이 있다는 인상을 주지 않는다. '냄새가 괜찮으니 먹어도 돼', '오래된 음식을 냉동하면 안전해' 같은 문구 금지.
소비기한 경과 표시는 '소비기한 경과 — 확인 필요'처럼 사실을 명확히 보여주며 먹도록 유도하지 않는다. 이전 지시서의 '상태를 확인한 뒤 소비하거나 폐기해줘' 문구는 사용하지 않는다.
제품 UI에 'V1' 같은 개발 버전 용어를 노출하지 않는다. 복원 미지원이면 '처리 후에는 되돌릴 수 없어.'라고 안내한다.

## 도메인 연결 범위
현재 구현을 확인한다. UI 제안만으로 냉동 30일 같은 임의 임계값·TOP3 정렬·부분 소비 규칙을 새로 만들지 않는다. 필요한 규칙이 없으면 누락으로 보고한다.
앞서 논의된 목표: 경과 음식은 TOP3와 분리; CREATE/CONSUME/FREEZE/MOVE/DISCARD 이력; 타 위치에서 냉동실 진입은 FREEZE, 냉동실에서 나갈 때는 MOVE; 소비/폐기 상태 변경 및 실행 전 확인; 복원은 기존 요구사항에 따름.
냉동일 입력의 의미는 '우리 집 냉동 보관 시작일'. 모르는 경우 오늘을 제안하되 수정 가능하게 하고 실제 과거 날짜인 것처럼 숨겨 확정하지 않는다.
이력은 당시 행동·시각·보관 위치·수량을 보여주고 음식명은 현재 이름을 쓴다는 앞선 제안과 현재 모델의 일치 여부를 확인한다. 이 패키지는 DB 변경 지시가 아니다.

## 검증과 보고
320/375/390/448px 및 데스크톱에서 가로 넘침, 긴 이름, 빈 목록, 로딩, 오류, 경과 데이터, 내비 가림, 이미지 실패를 확인한다. 탭 이동·포커스·다이얼로그 접근성, 44px 이상 터치 영역을 확인한다. reduced-motion을 존중하고 불필요한 무한 애니메이션 금지.
빌드 및 변경 위험에 필요한 핵심 검증을 수행하고 변경 화면·컴포넌트·사진 경로·확인 결과·미완료 보정 사항을 보고한다. 실제 구현하지 않은 보정·업로드·배포를 완료라고 보고하지 않는다.



## 최종 검증
asset-map.json의 default_enabled=true만 기본 자동 후보로 사용. pools 내 모든 키가 A 실제 파일에 연결되어야 한다. 잔디 제외 3개 키의 참조가 실행 코드에 남지 않아야 한다. 원본 비율·얼굴·발 표시를 작은 화면에서도 확인한다.
B를 사용한 경우 검수 ID, 사용 화면, 크기, 잘린 부분 처리 방식을 보고한다. 모호하면 후순위를 유지하고 질문은 필요한 사진에만 한정한다.
