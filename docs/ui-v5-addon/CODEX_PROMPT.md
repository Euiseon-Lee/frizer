# V5.2 추가 검수 우선 지시
이 ZIP은 이전 V5.1 추가 패키지 내용 전체와 신규 사진 3장을 합친 누적본이다. 기존 V5 Final은 별도로 유지한다.
photo-map-addon.json, PHOTO_REVIEW.md를 함께 읽는다. 기존 누끼형 기본 풀 A 5장 및 후순위 6장은 그대로다. 신규 JPG 3장은 별도 photo-frame 모드 전용으로, 기존 누끼형 empty 선택기에 넣지 않는다. 동일 PNG는 V5 relaxed-stretch로 이미 존재하므로 중복 등록하지 않는다.
사용자가 사진 프레임 방식도 선택하면 photo-frame 전용 풀을 연결한다. 그 전에는 사진 파일만 준비하고 현재 누끼형 빈 화면은 유지한다. 프레임 풀에도 아래 shuffle bag/리렌더 안정성 규칙을 적용하되 belly-rest 그룹 2장은 같은 화면 또는 연속 진입에서 겹치지 않게 한다. 후보 전체가 3장뿐이므로 그룹 조건 때문에 불가능하면 사진 개수보다 그룹 비반복을 우선하고 보류 후보는 다음 기회에 사용한다.
이번 파일은 JPG 배경 제거본이 아니다. CSS 배경 투명 설정만으로 사진 배경이 없어졌다고 처리하지 않는다. 전체 UI 변경이나 누끼 생성은 이번 패키지 적용 범위에 포함하지 않는다.

# V5.1 추가 이미지 및 빈 목록 다양화

기존 V5 Final 위에 적용하는 추가 패키지다. 전체 V5 대체 ZIP이 아니다. 기존 UI 색상·카피·도메인 로직은 유지한다. 이 지시에서 변경한 이미지 규칙만 V5보다 우선한다.

## 파일 적용
- asset-map-addon.json의 A 5장을 기존 static/assets/choco에 추가한다. 기존과 충돌하지 않는 extra- 키를 사용한다.
- B 6장은 reserve에 보관하고 기본 랜덤 풀과 선로딩에서 제외한다. 조건부 프레임 배치는 미리보기 확인 후 사용한다. 사진 수를 늘리기 위해 B를 자동 승격하지 않는다.
- 모든 11장에 V5와 동일하게 경계 2px 범위의 최소 알파 감소만 적용했다. RGB, 밝기, 색온도, 크기, 포즈, 리드줄, 소품은 바꾸지 않았다. 거친 실루엣과 원본 잘림을 복구한 파일이 아니다.
- 기존 empty-curious는 기본 빈 화면 풀에서 제거한다. 기존 파일 삭제는 불필요하며 초상 프레임 후보로만 보류한다. 잔디 제외 정책 유지.

## 빈 화면 후보
새 기본 풀: extra-chin-on-paw, extra-curled-smile, extra-sunny-sit, extra-tongue-step, extra-puppy-gaze.
기존 V5 후보는 별도로 실제 이미지를 확인하고 잘림 없는 독립 구도만 이 풀에 합칠 수 있다. 기존 empty 풀을 무조건 이어 붙이지 않는다.
각 화면별 한 장 고정 매핑을 폐기한다. 전체 목록 없음, 보관 위치별 목록 없음, 검색 결과 없음, 기록 없음에서 이 공유 후보 풀을 순환하되 각 상태에 맞는 문구와 버튼은 유지한다. 오류·로딩을 빈 목록으로 처리하지 않는다.

## 중복 방지와 안정성
1. 전역 빈 화면 선택기 한 곳에서 shuffle bag(후보를 섞은 뒤 하나씩 소비)을 관리한다. 화면마다 독립 Math.random 호출 금지.
2. 기본 5개 후보가 모두 사용되기 전에는 이미 사용한 후보를 다시 고르지 않는다. 가능한 경우 현재 화면에 보이는 다른 쪼코 이미지 키·poseGroup을 제외한다. 후보 그룹은 asset-map-addon.json 참고. 기존 V5 포즈 그룹은 실제 이미지 확인 후 지정한다.
3. 한 바퀴가 끝나 새로 섞을 때 직전 사진과 같은 사진으로 시작하지 않는다. 가능한 경우 직전 포즈 그룹도 피한다.
4. 남은 bag 후보가 현재 화면 이미지와 충돌하면 그 후보는 소비하지 않고 보류한다. 후보 전체가 충돌하는 경우 사진을 겹쳐 배치하는 대신 해당 보조 이미지를 생략한다. 다음 진입 때 재선택한다.
5. 선택은 '빈 상태에 새로 진입'할 때 1회만 한다. 동일 화면 리렌더, 입력, 재조회 중 계속 빈 상태, 화면 크기 변경에는 기존 선택을 유지한다.
6. 보관 위치 변경 등 의미 있는 빈 화면 컨텍스트 변경, 화면을 떠났다 재진입, 목록이 있다가 없어짐은 새 선택으로 취급한다. 개발 모드 이중 렌더로 bag이 두 번 소모되지 않게 한다.
7. bag 잔여 목록·직전 key는 버전이 붙은 sessionStorage 키로 보존해 새로고침에도 한 사진이 반복되지 않게 한다. 저장소 접근 실패 시 메모리 상태로 정상 작동한다. 사용자 식품 데이터는 저장하지 않는다.
8. 후보 변경 시 오래된 저장 키를 정리하고 유효한 key만 복원한다. 이미지 로드 실패는 다른 유효 후보로 제한적으로 대체하고, 모두 실패하면 사진 없이 빈 상태 안내를 보여준다. 무한 재시도 금지.

## 배치
- 사진 공통 영역은 출발점으로 약 160×150px. object-fit: contain, 비율 유지, 투명 여백 포함. 가로·세로 구도 모두 중앙 정렬한다.
- 실제 원본 구도를 유지한다. 확대 crop/cover, 잘린 신체 생성 금지. 텍스트와 버튼을 가리지 않는다.
- 새 A 후보는 몸통 경계를 카드 하단에 감추는 방식에 의존하지 않는다. 카드 내부 여백을 둔다.
- 필요한 이미지부터 로드한다. 원본·reserve 전체를 앱 public에 복사하지 않는다.

## 확인 및 보고
- 기본 5장 순회 시 첫 5회 중복 없음, 다음 회차 경계 연속 중복 없음 확인.
- 리렌더 중 유지, 재진입 시 순환, 새로고침 복원, 저장소 실패, 후보 고갈 및 이미지 실패 확인.
- 320/390/448px에서 가로·세로 사진 각각 버튼/텍스트 겹침 및 추가 잘림 확인.
- 실제 src/currentSrc를 추적하고 변환 없이 복사한 PNG는 manifest SHA-256과 비교한다. 원본이나 reserve를 잘못 참조하지 않는다.
- 구현 완료 후 사용 후보, 선택기 위치, 확인 결과와 실제 빈 화면 미리보기를 보고한다.
