# ADD — 검수 완료 쪼코 이미지 20장

이 ZIP의 `images/`에 들어 있는 20장은 사용자가 직접 검수하고 사용을 승인한 이미지다.
기존 이미지 시스템을 교체하지 말고, 현재 프로젝트에 추가하는 방식으로 작업한다.

## 필수 처리 순서

1. 프로젝트의 기존 이미지 파일, Registry, 이미지 선택 코드와 CSS를 먼저 확인한다.
2. `images/`의 20장을 기존 파일과 비교한다.
3. 바이너리 해시가 같거나 동일 원본의 리사이즈·재압축본인 경우에만 중복으로 판정한다.
4. 포즈나 분위기가 비슷할 뿐 다른 사진이면 별도 이미지로 유지한다.
5. 동일 이미지가 기존에 있으면 신규 파일을 복사하지 않고 기존 파일을 Registry에 재사용한다.
6. 중복이 아닌 파일은 20장 모두 프로젝트의 기존 이미지 경로에 추가한다.
7. 추가된 파일은 실제 사용 그룹에 등록한다. 파일만 복사하고 미사용 상태로 남기지 않는다.
8. 기존 승인 이미지는 삭제하거나 역할을 임의로 축소하지 않는다.

## 사용자 지정 특별 정책

### `pink-coat-look-back.png`

- 좌절·아쉬움 이미지로 취급한다.
- 오류, 실패, 결과 없음, 아쉬운 빈 상태에 사용한다.
- 일반적인 밝은 헤더 후보에서는 제외한다.
- 기존 오류 그룹에 추가한다.
- 오류 그룹 안에서 순환하며 특정 오류에 항상 같은 한 장만 고정하지 않는다.

기존 오류 그룹과 합친 후보는 다음과 같다.

```text
puppy-sit.png
empty-curious.png
extra-chin-on-paw.png
extra-puppy-gaze.png
pink-coat-look-back.png
```

오류 화면에는 반드시 이 그룹의 이미지를 사용한다.

### `back-view-harness.png`

- 기존 `happy-closeup.png`와 함께 프로필 이미지로 사용한다.
- 프로필 풀은 최소한 다음 두 장을 포함한다.

```text
happy-closeup.png
back-view-harness.png
```

- 세션 또는 날짜 단위로 선택해 한 화면 안에서 불필요하게 변경되지 않게 한다.
- 뒷모습과 하네스가 과도하게 잘리지 않도록 `object-fit: contain`을 우선한다.

### `calm-closeup.png`

- 웃음·슬픔보다 무표정에 가까운 중립 이미지다.
- 일반 상태, 확인 대기, 목록·상세 조회, 중립 안내와 일반 헤더에 사용할 수 있다.
- 성공 전용이나 오류 전용으로 분류하지 않는다.

## 나머지 이미지 배치 원칙

나머지 신규 이미지는 감정을 지나치게 세분화하지 않는다. 원본 비율, 피사체 크기와 현재 UI 슬롯 크기에 따라 배치한다.

- `side-rest.png`, `belly-up-lounge.png`: 가로형 빈 상태, 넓은 안내 영역, 카드 하단
- 세로형 전신·반신 이미지: 모바일 빈 상태, 카드 옆 장식, 세로형 안내, 모바일 헤더
- 정사각형에 가까운 이미지: 작은 상태 카드, 프로필형 슬롯, 중립 안내
- 꽃·장식 이미지도 계절 한정으로 제한하지 않고 일반 헤더와 편안한 상태에서 사용 가능

꽃·장식 관련 신규 이미지:

```text
flower-sniff.png
flower-collar-sit.png
plastic-flower-hat.png
snack-ring-tilt.png
striped-socks-puppy.png
```

기존 `leaf-hat-front.png`, `leaf-hat-side.png`도 계속 유지한다.

## 렌더링 원칙

- PNG 투명 배경을 유지한다.
- JPEG로 변환하거나 임의로 재압축하지 않는다.
- 얼굴, 귀, 꼬리, 발, 꽃, 옷과 장식을 강제로 자르지 않는다.
- 기본적으로 `object-fit: contain`과 적절한 `object-position`을 사용한다.
- 이미지마다 동일한 고정 width/height를 강제하지 않는다.
- 기존 최적화 절차가 있을 때만 동일한 절차를 적용한다.
- 방향을 임의로 좌우 반전하지 않는다.

## 순환 정책

사용 이력은 용도별로 분리한다.

```text
PROFILE
HEADER
ERROR
EMPTY
SUCCESS
CALM
WIDE
PORTRAIT
```

- 일반 영역과 오류·빈 상태가 하나의 sessionStorage 이력을 공유하지 않게 한다.
- 그룹별 shuffle-bag 방식으로 후보를 한 번씩 사용한 뒤 다시 섞는다.
- 같은 화면에서 동일 이미지가 중복 노출되지 않게 한다.
- 적합한 후보가 있는데 최근 사용됐다는 이유로 이미지를 생략하지 않는다.
- 이미지 로딩 실패 시 같은 그룹의 다른 후보로 한 번 대체하고 레이아웃을 유지한다.

## 변경 제한

이번 작업은 이미지 추가와 매핑 확장이다. 다음 항목은 필요한 범위 외에는 변경하지 않는다.

- 페이지와 컴포넌트 구조
- 색상과 타이포그래피
- 서비스 문구
- 재고 기능과 API
- 모바일 Navigation
- 이미지와 무관한 Backend 로직

## 필수 검증 및 완료 보고

`image-mapping.csv`의 20개 행을 기준으로 각 원본을 반드시 다음 중 하나로 분류한다.

- `ADDED`: 신규 파일 추가 및 실제 사용 그룹 등록
- `REUSED`: 기존 동일 이미지 재사용 및 실제 사용 그룹 확인

허용하지 않는 결과:

- 누락 또는 미확인
- 복사됐지만 Registry에서 미사용
- Registry에는 있지만 실제 파일이 없음
- 이름 충돌로 기존 파일 덮어쓰기
- 비슷한 자세라는 이유만으로 제외

완료 보고 표:

| ZIP 파일명 | 결과 | 최종 프로젝트 파일명 | 사용 그룹 | 중복 판정 근거 |
|---|---|---|---|---|

20개를 모두 기재하고 다음 수식을 확인한다.

```text
ADDED 수 + REUSED 수 = 20
누락 수 = 0
```

추가로 다음을 검증한다.

- `pink-coat-look-back.png`가 오류 그룹에 있고 일반 헤더에서는 제외됨
- `back-view-harness.png`와 기존 `happy-closeup.png`가 모두 프로필 풀에 있음
- `calm-closeup.png`가 중립 그룹에 있음
- 꽃·장식 이미지가 실제 후보에 포함됨
- 승인 이미지 중 사용처가 없는 파일이 없음
- Registry에 등록된 모든 경로가 실제 파일로 존재함

완료 보고 후 작업을 중단하고 사용자 확인을 기다린다.
